# 视频

**Status: Existing（已实现）**
**权威实现：** `autodrive_console/video.py`、`web_console.py`、`frontend/src/liveObservation.js` 和 `mobile/lib/features/live_observation/`
**消费者：** `robot_backend`、`web_console`、`mobile`
**兼容性：** 优先增量变更；破坏性变更必须同时更新所有消费者和本文档。

`GET /api/video/status` 返回已配置的视频流和运行时健康状态。`POST /api/video/control` 是客户端控制全局或单路启用状态的唯一入口。客户端必须使用返回的已配置流名称，不能自行拼接相机端点。

实际视频像素通过媒体网关到浏览器或 Mobile 的只接收 WHEP/WebRTC 会话传输。Python 只管理配置、进程生命周期和健康状态，不转发视频帧。离开视频工作区、切换流、App 进入后台或销毁视图时，必须释放对应会话、PeerConnection、媒体流和 renderer。

## 发布默认值与已有配置迁移

2026-10-16 文档对齐：本节描述已有 Backend 行为，不增加字段或改变 Web、移动 Web、Flutter
消费者协议。ZIP 替换保留 `config/video.json`，启动时 `VideoManager.migrate_config()`
仍可能受限更新该文件：补齐发布模板中缺少的流、移除 camera_pair 旧元数据、迁移精确匹配
旧默认的 Intel 编码器/设备组合为 auto；在 ShmSDK 发布配置下，将精确匹配旧默认物理相机
ROS 话题的输入迁移为对应 ShmSDK 通道。自定义输入不按该规则转换。

没有自动的 ShmSDK→ROS 反向迁移；安装 ROS 包或回退 ZIP 不会自行还原已经保存的 ShmSDK
输入，须走维护配置恢复流程。四路初始默认值取决于发布模板，不能把换包等同于覆盖已有配置。
这与私有运行时刷新、内部端口兜底不回写配置分别属于不同操作。

## 2026-10-13 兼容性增量与消费者影响

**Status: Existing（已实现并通过本地回归；实车 GPU/端到端性能尚待验收）**

- 运行执行方：Backend 管理受控硬件编码能力、逐路进程恢复与状态；C++ 仅旁路读取明确指定的 ROS Image 或 ShmSDK Cam 通道；不猜测切换源。
- Existing 消费者：Desktop Web、移动 Web 与 Flutter Mobile。原 `enabled/gateway/streams` 字段、`online/waiting/offline/disabled` 状态、已配置流名和 H.264 WHEP URL 保持兼容。增量 `runtime` 诊断包含状态/选择编码器/错误说明；客户端忽略未知字段仍可读取原状态。
- 增量诊断结构：`runtime={state:disabled|starting|ready|error, encoder:vaapih264enc|nvh264enc|null, device:string|null, error_code:string|null, detail:string}`；每路可增加 `error_code/detail/retry_count`。这些字段均可缺省，旧客户端不能因未知字段或未提供增量字段而拒绝响应。
- 车辆配置 `runtime.encoder` 增量允许 `auto/vaapih264enc/nvh264enc`。auto 先验证已有 Intel VAAPI 路径，再验证 NVIDIA NVENC；不自动采用软件编码。探测仅在显式启用视频时进行，并有期限/结果缓存。旧缺省 Intel 设置通过 `hardware_selection_version=1` 只迁移一次，之后保留明确硬件选择。`vaapi_device` 可为 auto 或受限 `/dev/dri/renderD数字` 路径，不成为浏览器文件访问接口。
- native `--encoder` 为受控 Backend 选择的 VAAPI/NVENC；旧缺省调用仍允许 VAAPI。帧继续通过本机 fd 交给原生编码器，不经 HTTP/Python；输出 resolution/fps/bitrate 预算保持。
- 输入兼容增量处理 JPEG/JPG/MJPEG、RGB/BGR 别名、常见单/四通道及明确排列的 YUV422；JPEG 以受限内容头校验，raw 以实际尺寸/stride/长度校验。新鲜帧只保留最新槽，限帧后才做昂贵解码。
- 一路输入异常只重试该路，退避有界且不重启其它路/MediaMTX；正常停用不重试。无可用硬件编码器明确报错，不能把网关 API 在线当作编码可用。
- Web 必须通过实际解码首帧判定播放，设置 WHEP/首帧期限并正确释放过时会话。Flutter 原 HTTP 期限与过时响应清理保持；本次不改变其原字段/枚举，验证其现有解析兼容增量状态。
- 验证影响：Backend/native 格式、硬件选择、隔离恢复、打包依赖；Web 生命周期与诊断；Mobile 定向既有视频解析/WHEP 消费检查，原 API 不引入新强制字段。本机 Mobile 仅完成既有解析的静态兼容核对，Flutter 工具链未安装，未声称移动端真机验收。

## 2026-10-14 冷启动与恢复影响

消费者为 Backend、Web、Mobile；原 API 字段与枚举保持兼容，无新增客户端必填字段。
NVENC 预检最多十秒、可取消；VAAPI 保留四秒。NVENC 各输入进程依次启动，上一流发布 H.264
或十二秒等待到期后才启动下一路，缺失输入不能永久阻断其他路；启动结束后不增加持续轮询。
原生编码管线保留总计十秒的初始化写入窗口，不能把第一次成功写管道当作编码初始化完成；
窗口结束后保留 250 毫秒背压期限。管线失败后按 1/2/4/8/16/30 秒退避，只影响该路；
连续成功提交满六十秒才重置退避。始终只保留最新输入，不积压历史帧，不自动软件编码。
日志区分创建进程、输入到达、编码提交失败；GStreamer 警告进入既有视频日志。
验证范围为 Backend/native 生命周期、超时与取消；Web/Mobile 原消费字段不变，无新平台依赖。
这些保护不等同于确认现场驱动阻塞根因或完成新车验收。

## 2026-10-14 NVENC 时间轴衔接

本次影响仅为 Backend 拥有的原生视频管线；Web/Mobile 的 H.264、WHEP URL、状态字段、
分辨率、帧率与码率均不变，无客户端代码或新平台检查依赖。

保留 `fdsrc do-timestamp=true` 的实际输入时间轴。NVENC 管线在 `rawvideoparse` 后、原有队列前，
先以 `identity sync=true` 等待 PLAYING，再由独立的 `identity drop-buffer-flags=discont` 丢弃
启动时可能没有有效时间戳的完整首帧，避免首个 segment 未偏移、后续帧才应用 NVENC 偏移，
使 RTSP 发布器等待远未来帧。两步不可合并：同一 identity 会先执行丢弃而跳过同步。
VAAPI 参数保持不变；仍只有编码前的单帧 latest-wins 队列，不增加历史缓冲。
验证必须覆盖并发启动、首个编码输入的有效且接近运行时间的 PTS、持续媒体字节增长、
实际 WHEP 解码及短暂断流恢复后的抖动缓冲，单次 ready 或首帧不足。

## 2026-10-14 私有 RTSP 端口冲突

影响范围为 Backend 拥有的 MediaMTX 和原生发布器；Web/Mobile 的 API、WHEP 地址与视频预算
均不变，不新增客户端依赖。启动私有网关时，优先使用配置的回环 RTSP 端口；若已被占用，
只为本次运行选择空闲回环端口，同时用于网关监听和所有原生发布器。运行中单路启停、重试
仍沿用本次选定端口，不能被重新读取的原始配置覆盖。

不得停止或修改占用端口的外部服务，不回写用户 `config/video.json`，不迁移对外 WHEP/API
端口。候选耗尽或非占用类 socket 错误应明确失败，不无限重试。端口检查是本机 bind 检查，
不向机器人已有服务发送探测连接。验证包括真实端口占用、网关/发布器一致性及配置保持。

## 2026-10-15 Web 短暂断连恢复

影响仅为 Desktop Web 与移动 Web 的播放器生命周期；Backend、Flutter Mobile 的协议、
WHEP 地址、输入源与视频预算不变，不引入新的平台依赖。

WebRTC `disconnected` 后保留原连接和最后解码画面，最多等待五秒自然恢复，明确显示
“连接波动”；重复断连通知不能延长期限。连接恢复后仍显示“等待画面恢复”，直到收到
新解码帧才恢复“播放中”。期限到期或 `failed/closed` 时释放会话并按原退避重连。
关闭视频、离开工作区或销毁播放器仍立即释放全部资源；过时回调不得影响替换后的连接。
不新增持续统计轮询或帧队列，首帧与解码停滞期限继续生效。

Web 的状态查询最多同时一个、五秒超时，关闭页面时取消；视频开关会取消先前查询，
过时结果不能覆盖控制响应。响应损坏或查询失败仅报告诊断，不以缺省空对象停掉正常视频。
全局和单路控制请求均设十五秒响应期限；超时仅表示结果未确认，释放等待状态后重新查询，
不自动重复 POST，避免已经生效的开关操作被反复执行。关闭页面取消尚未完成的控制请求。
沿用三秒本地检查节奏检测解码停滞及逐路重连，不等待 HTTP 查询完成；只使用 Backend
最近确认的已配置流和 WHEP 地址，不发现新来源。隐藏页面或离开移动相机工作区立即释放
播放会话，重新显示时恢复；不修改 Backend 的全局视频开关。
实时性优先：不增加历史帧队列。沿用三秒检查节奏，若最后解码帧已超过一秒则标为
“画面停顿”，不继续声称实时播放；新解码帧到达后清除提示，八秒停滞仍按原期限重连。
失败流的三秒退避结束后，由该流的一次性定时器立即尝试恢复，避免再等一轮状态检查；
定时器受播放器所有权、关闭、后台与页面退出清理约束，正常播放不增加定时轮询。
旧 WHEP 会话的 DELETE 是有界尽力清理：活动页面内使用普通可取消请求，最多等待 1.5 秒，早于三秒重试期限；
不读取无用途的响应正文，避免故障连接长期占用浏览器 HTTP 连接池。
2026-10-15 清理补充仅影响 Desktop/移动 Web，Backend 与 Flutter 的接口和视频参数不变：
网络错误、超时、HTTP 408/429/5xx 时保留该旧会话清理地址，分别退避一秒、两秒，
总计最多三次 DELETE；同一地址同时只允许一个清理序列，不等待清理完成才恢复播放。
成功、404/410 或其它永久客户端错误均停止；页面退出后不再发起定时重试。
本项只清理重复远端 reader，不限带宽、不调整码率/帧率/分辨率，不保留旧 peer 或旧帧。
退出页面时仍使用 keepalive 尽力提交；页面销毁或断网时不保证远端清理请求完成。
Web 后台、离开移动相机工作区或停用播放器时，连同视频纹理一起释放 GPU renderer 和
尺寸观察器；异步初始化的旧 renderer 不得在退出后重新挂载，也不得覆盖返回后的新初始化。
正常前台网络重连仍复用该卡片的 renderer，避免反复创建 GPU 上下文。本项仅影响 Web
资源生命周期，Backend、Flutter Mobile 的接口、视频预算和现有消费方式保持不变。

## 2026-10-15 视频带宽日志（Existing）

仅影响 Backend 视频运行器的本地诊断，Web/Mobile 原 API 字段、视频参数、WHEP 与帧链路不变。
运行器以独立可停止的低频工作线程每五秒读取受控回环 MediaMTX 的 WebRTC 会话列表，
累计字节按会话身份与单调时间差计算，按已配置路径汇总每路发送 Mbps、MB/s 与连接数。
优先读取 `outboundBytes`，兼容旧 `bytesSent`，分页与响应大小有界。
只统计本工具已配置路径的 read 会话；多观看端分别计数并相加。
连接身份变化或计数回退先重建基线；统计失败标为不可用，不能冒充零带宽。
日志同时进入 `video-runtime.log` 原有 stdout 与结构化工具日志的 video 模块；
稳定观看每三十秒一条，无人观看不重复打印，状态/连接数量变化时提示一次。
这是网关字节计数速率，不是抓包线速、Wi-Fi 空口占用或系统网卡总流量；
不包含 IP/以太网/Wi-Fi 的额外开销，不能与配置编码码率混为一谈。
请求仅回环，socket 空闲和每次请求总期限均为 0.5 秒（总期限主动 shutdown 本统计 socket）；停止时中断当前请求并取消后续采样。统计线程资源不足只报统计不可用，子进程清理由 finally 保证；不在编码/媒体循环中阻塞等待，
不抓视频帧、不增加浏览器连接、不调整码率，不调用 ROS 或外部进程。

### 编码输入与发送量对照

Backend 诊断增量读取同一受控回环网关的 paths 输入计数，按发布者身份、上线时间与
单调时间计算每路编码输入速率。Web/Mobile 的接口、H.264/WHEP 消费方式与编码参数不变。
发送基准为每路源输入乘以该路观看连接数；只有基线有效、两类查询前后端点偏差与
请求耗时均不超过较短采样间隔的 1% 时，才计算近似倍率（默认五秒对应 50 ms）。
这是诊断时间误差门限，不影响媒体或车辆控制；窗口明显错位时倍率未知，各自速率仍显示。
即使门限内仍存在突发帧与不同层级计数的开销差异，不能将倍率等同于重传率。
编码输入总量仅在所有受控流的输入速率有效时给出，不能将部分源的和冒充完整总量。
源查询失败、发布者变化、计数回退或源未就绪均标记未知，不影响已有 WebRTC 发送统计。
源请求沿用现有分页、响应大小、期限、可停止线程与低频日志边界；不调整媒体流量。

### NVENC 源码候选策略（待实车验收）

Backend 可选 `runtime.nvenc_rate_control: "vbr"` 用于本地参数核验与后续同源实车对照。
省略或显式 `"cbr"` 保持既有默认；仅允许这两个字符串，不自动迁移已有配置。
候选使用原 bitrate_kbps 作为平均与最大码率参数、const-quality=23，保持帧率、分辨率、
baseline、无 B 帧、zerolatency、GOP 与启动时间轴。画质目标不是画质等价保证，最大码率
参数也不是任意瞬时线速上限；未验收前不自动启用候选。VAAPI 参数保持不变。
硬件选择缓存包含该策略，预检与 native 管线使用相同策略；本次运行冻结已预检选择，
运行期间修改配置文件在下次运行生效。native CLI `--nvenc-rate-control` 省略默认 cbr。
Web/Mobile 继续消费相同 H.264/WHEP，无新增必需客户端字段，不引入其他平台工具链。

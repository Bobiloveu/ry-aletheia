# 手动重定位全面修复计划

**目标：** 地图可用时，无论定位正常、自动重定位卡住、服务失败或实时位姿中断，PC 均可直接拖动车体、找回图标并设置朝向；本地预览不调用机器人服务。

**方案：** 独立管理本地预览与已提交快照。一个“确认重定位”入口按需建立停车占用、等待真实确认后提交；保留后端互斥、运行实例/配置、真实地图、两阶段请求和定位完成核验。删除要求先点“保持停车重新对齐”的 UI 流程。

**技术栈：** 现有 JavaScript/PixiJS、Python ROS2 受控 Backend；不增加依赖，不迁移目录。

**约束：** 保留其他工作区修改；不打包、不部署、不对真实机器人下发指令；Mobile 不消费本组端点。

- [x] Backend：从实际 GetMap 栅格绑定 source_map_id，拒绝预览源图不匹配及无法按现有坐标渲染的地图原点。
- [x] Backend：准备阶段也在实际发送前复核地图、进程、文件与停车占用；并发动作立即拒绝，状态查询保持可用。
- [x] Web：本地编辑不依赖 can_apply、定位状态、服务可用性或实时位姿；直接拖动车体进入预览，一键找回随时可用。
- [x] Web：确认入口自动停车/等待/提交；请求的位姿、配置与源图不可变；取消预览不恢复驾驶。
- [x] Web：失败和轮询错误保留预览；新预览不被旧请求的回调或计时器清除；真实切图清除旧坐标并提示。
- [x] Web：核对鼠标/触摸、缩放、面板滚动、Esc、部分切图失败及 HTTP 丢响应恢复。
- [x] 契约与用户说明同步；定向 Backend/Web/离线检查、浏览器真实控制器场景、独立复核。
- [x] 按上述完整需求审计证据后完成目标，明确源码与现场部署状态。

# 部署建图工作台 v2 重构计划（已执行）

> 状态：用户已批准，前端实现与验证已完成；保留本计划作为变更与验收记录。
>
> 范围：仅 PC Web 部署建图页面；不修改 Mobile、Unity、ROS topic、后端 API、部署包格式或地图业务规则。

## 1. 这次要解决的真实问题

1. “创建项目”阶段是一个窄卡片，右侧大片空白；创建项目、已有项目和流程说明彼此分散，现场人员不知道下一步应该做什么。
2. “准备地图”阶段因为画布使用了 `data-deployment-stages="annotations localization"`，工作流切到 `maps` 时画布被隐藏；地图已经导入也无法立即看到和确认。
3. 页面离开后重新进入时，`selectedProject` 和 `viewedDeploymentStage` 是内存变量，当前页面没有恢复指针；因此会回到未选项目/第 1 步，造成“又得重新开始”的错觉。
4. 顶部向导、当前动作卡、阶段卡、右侧配置卡重复表达同一状态，形成“为排布而排布”的卡片墙；步骤导航、工作区和校验信息没有明确的主次关系。
5. 阶段虽然有 gating，但画布、地图列表、路线编辑和导出控件的生命周期不连续，导致用户在不同阶段丢失上下文。

## 2. 设计决策（先定原则，再动代码）

### 2.1 主结构：持续存在的部署工作台

采用单一工作台，而不是继续堆叠阶段卡片：

```text
┌ 应用导航（保留现有） ──────────────────────────────────────────┐
│ 项目 / 当前任务                         保存状态   退出项目      │
│ ①项目  ─ ②地图  ─ ③标记  ─ ④定位  ─ ⑤校验导出（紧凑阶段轨道） │
├──────────────┬──────────────────────────────┬─────────────────┤
│ 左侧上下文栏  │ 中央主工作区                 │ 右侧检查器       │
│ 项目/地图槽位 │ 当前阶段唯一主任务             │ 当前选择的配置/校验 │
│ 当前地图列表  │ 地图画布在 ②③④ 阶段持续挂载    │ 无选择时显示说明   │
├──────────────┴──────────────────────────────┴─────────────────┤
│ 返回 / 保存草稿 / 继续下一步（固定在工作区底部）                 │
└─────────────────────────────────────────────────────────────────┘
```

- 顶部只保留一次进度信息，不再同时渲染“大型引导卡 + 当前动作卡 + 阶段内容”。
- 已完成阶段可回看；未解锁阶段显示锁定原因且不能获得焦点；正在执行/已导出的阶段按现有业务规则只读。
- 使用 `frontend-design` 的产品化层级和 `impeccable` 的 Operate 模式；`design-taste-frontend` 只借用其反模板化、减少装饰的检查项，不把 landing page 的布局模式套到本控制台。

### 2.2 地图画布是连续上下文，不是阶段专属卡片

- 项目创建后，只要存在可展示的地图，画布容器始终存在。
- `maps`：预览、缩放、适配视图、选择地图；禁止标记写入。
- `annotations`：开启组件/起点/目标等标记工具。
- `localization`：保留同一张画布和缩放状态，叠加定位绑定/路线语境。
- 画布切换阶段时不销毁 DOM、不重新加载图片、不重置活动地图；只切换能力模式。

### 2.3 恢复的是“用户指针”，不是复制业务事实

后端项目数据仍是唯一事实来源；浏览器只保存以下轻量会话指针：

```js
{
  version: 1,
  projectId: "…",
  mapId: "…",
  viewedStage: "maps",
  savedAt: "…"
}
```

加载时重新请求项目并运行 `deriveDeploymentWorkflow`，然后：

- 项目存在且阶段仍已解锁：恢复项目、地图和回看阶段。
- 阶段已失效：回退到服务端当前阶段，并解释原因。
- 项目/地图被删除或指针损坏：清理指针，回到项目启动页，不显示旧项目假象。
- 不把表单内容、组件数据、路线数据写入 localStorage。

## 3. 分阶段实施计划

### 阶段 A：先建立可测试的状态边界

**目标：** 解决离开/返回丢失进度，同时不改变 API。

**文件：**

- 新增 `autodrive_console/web/deployment/session-state.js`
- 修改 `autodrive_console/web/deployment.js`
- 修改 `autodrive_console/web/deployment/workflow.js`（仅补充阶段/可见性派生，不改业务完成条件）
- 新增 `frontend/test/deployment-session-state.test.mjs`
- 更新 `frontend/test/deployment-workflow.test.mjs`

**实现：**

1. 抽出 `readSessionPointer / writeSessionPointer / clearSessionPointer / clampViewedStage` 纯函数。
2. `openProject` 成功后写入项目指针；活动地图、阶段切换时写入指针。
3. `loadProjects` 完成后尝试自动打开最近项目；项目不存在时安全回到项目启动页。
4. 页面 `pageshow`/重新获得可见性时只重新校验服务端事实，不覆盖用户正在编辑的草稿。
5. 明确 `currentStage`（服务端事实）和 `viewedStage`（用户回看）两个概念，避免刷新后阶段错乱。

**验收：**

- 进入其他导航再返回、刷新、重新打开同一 URL，项目/地图/可访问阶段恢复。
- 删除项目或旧阶段后不会恢复到幽灵状态。
- 现有工作流单测仍通过。

### 阶段 B：重排页面骨架，消除重复信息

**目标：** 把“阶段导航、工作区、检查器”建立成单一层级。

**文件：**

- 修改 `autodrive_console/web/deployment.html`
- 修改 `autodrive_console/web/deployment.css`
- 修改 `autodrive_console/web/deployment.js`

**实现：**

1. 保留现有业务 DOM id 和事件入口；只移动容器和补充语义属性，避免 API/监听器回归。
2. 把顶部大型“按顺序完成部署”压缩为紧凑阶段轨道，保留当前阶段、完成数和阻塞原因。
3. 新增明确的 `deployment-workbench`、`deployment-context-rail`、`deployment-main-surface`、`deployment-inspector`、`deployment-actions` 容器。
4. 去掉重复的当前动作卡；当前操作标题、原因和唯一主按钮只在工作区头部出现一次。
5. 将项目列表、创建项目、场景选择改为“启动工作区”，不再以窄卡片占据左侧并留下空白主区域。
6. 只对当前阶段渲染可操作控件；锁定阶段保留一行状态摘要，不渲染可聚焦表单。

**视觉约束：**

- PC 优先：1366×768 和 1920×1080 为主要验收尺寸，1024 宽度将右侧检查器折叠为抽屉。
- 深色石墨底、单一系统蓝主色、绿/琥珀/红语义色；减少大面积发光和重复边框。
- 统一 14/16/20/28 字级、10–12px 圆角、8–10px 控件圆角；优先使用分隔线和留白，不继续增加卡片。
- 保留现有导航体系和中文业务术语；不改 Mobile 样式。

### 阶段 C：重做创建项目工作区

**目标：** 首次进入页面就能理解“继续已有项目”或“创建新项目”两个选择。

**交互：**

- 有最近项目：顶部显示“继续上次项目”主入口；项目列表用于切换，创建新项目为次入口并原地展开表单。
- 无项目：中央显示创建表单，场景模型选择与项目名称在同一上下文内完成。
- 创建成功后不跳到空白页，直接进入“准备地图”，左侧显示新项目摘要，中央显示待导入地图工作区。
- 项目切换需二次确认未保存草稿，保存/放弃选项清晰可见。

**验收：** 创建区不再是窄卡片；主要操作位于首屏可见区域；已有项目和新建项目不会同时争夺主视觉。

### 阶段 D：重做准备地图工作区

**目标：** 导入后立即看到地图，并能知道还缺什么。

**交互：**

1. 左侧地图槽位显示“待导入/已导入/校验失败/已确认”状态和缩略信息。
2. 中央画布在 `maps` 阶段立即可见；导入前显示有意义的空状态和选择文件主按钮。
3. 导入采用三步侧窗：选择文件 → 清单校验 → 确认导入；成功后自动选中并渲染地图。
4. 右侧只显示当前地图名称、地图阶段、文件校验和下一步；不提前显示标记/路线表单。
5. 任意非空 `.pcd` 有效，`index.txt` 仅作兼容文件；缺 YAML/PGM/PCD 的错误分别提供修复动作。

**验收：** 用户在地图阶段不需要进入标记阶段就能看到、缩放和确认导入的地图；地图不会因阶段门控而消失。

### 阶段 E：标记、定位和校验导出采用能力模式

**目标：** 保留现有业务功能，但让每一步只出现当前工具。

- `annotations`：中央画布 + 标记工具条；右侧显示选中组件属性；路线和导出控件不参与焦点序列。
- `localization`：中央画布 + 当前地图定位上下文；右侧只显示绑定/路线编辑；标记工具改为只读摘要。
- `export`：显示校验清单、失败原因和预览/下载；编辑工具收起，允许返回受影响阶段。
- 缺 Transition/电梯关联/地图顺序等问题，错误直接定位到左侧对应地图槽位或右侧修复入口，不再使用泛化“补齐地图衔接”卡片。

### 自动化

```bash

node --check autodrive_console/web/deployment.js

```

如触及定位清单兼容逻辑，再运行对应的 `tests/test_location_manifest.py`；不因本次纯前端布局重构引入无关后端依赖。

### agent-browser 场景

逐项截图并记录结果：

1. 无项目首次进入：创建区首屏可操作，无大块孤立留白。
2. 已有项目自动恢复：离开页面再回来，项目/地图/阶段保持。
3. 准备地图：已导入地图始终可见；选择、校验、导入反馈在同一工作区完成。
4. 缺 YAML、缺 PGM、缺 PCD、只有任意命名 PCD、没有 `index.txt`。
5. 标记阶段：只有标记工具可操作；定位/导出控件不可聚焦。
6. 定位阶段：同一画布保留缩放和活动地图，错误可直接定位修复。
7. 校验导出：失败和成功均有明确下一步；返回前一步后状态恢复。
8. 1366×768、1920×1080、1024 宽度：无主区域空白、重叠、横向溢出或按钮跑出首屏。

### 验收门槛

- 准备地图阶段能看到地图，这是阻塞性验收项。
- 离开/刷新/重开后不会回到第 1 步，这是阻塞性验收项。
- 后续阶段未解锁时不可操作且不可获得键盘焦点。
- 创建项目、地图导入、标记、定位、导出每阶段只有一个明确的主动作。
- 不改变现有后端 API、ROS、地图坐标和部署包格式。

## 5. 风险与回滚

- **风险：** 现有 `deployment.js` 事件监听依赖 DOM 位置或旧的面板结构。
  **控制：** 先保留现有 id/字段和事件入口；每次只迁移一个阶段，并运行现有前端测试。
- **风险：** 本地恢复指针与服务端项目事实不一致。
  **控制：** 指针只保存 id；每次恢复都重新请求并用 `deriveDeploymentWorkflow` 校正，失败即清理。
- **风险：** 画布持续挂载导致阶段间误写。
  **控制：** 能力模式由阶段派生，非当前阶段工具 `disabled` 且事件处理器拒绝写入。
- **回滚：** 所有改动限定在 Web 文件和新增前端测试；若某一阶段视觉验收失败，可单独回退该阶段容器，不影响后端和已有部署数据。

# 固定任务线路与自动定位信息

## 已确认需求

- 复用现有目标点与过渡点，不新增取货组件。
- 支持多个取货点、多个送货目标、同一点的多次访问，并保存多条具名固定线路。
- 人员只编排去程，后端自动派生返程；返程不重复执行取货、卸货、开关仓。
- 常开门使用 `normal` 过渡点，无动作、非单点停靠。
- 地图用途、楼栋、单元来自地图实例，不再逐图确认定位配置。布局模板是稳定内部标识，不能当作真实楼层。
- 仅修改项目快照和实验导出，不构建、不部署、不控制机器人、不修改来源地图。

## 用户流程

地图准备 → 标记位置 → 配置任务线路 → 校验与导出。

“配置任务线路”以内联有序列表为主：选择线路或新建线路，指定既有起点，逐项添加目标点、
过渡点和通行设施。支持上移、下移、删除和再次添加同一个位置，键盘也可操作。地图显示
对应去程顺序。人员为每次目标访问指定取货、送货或仅到达；仓控操作独立选择仓位与方式。
地图定位信息折叠只读展示；遗留无地图实例项目保留旧绑定 API 的兼容能力。

同一目标位置可以在不同线路或同一线路的不同访问中执行不同仓控动作，故动作属于线路访问，
位置组件保留既有默认属性。取货默认推荐开仓，送货推荐自动卸货，但不将业务用途与操作码绑定。
开仓成功仅按既有仓控节点的成功条件完成，不新增或虚构人工装货完成协议，也不自动追加关仓。

## 项目模型

新增项目所有的 `task_lines: []` 和 `active_task_line_id: null`。线路包含：

```json
{
  "id": "task-line-abc",
  "name": "超市取货配送",
  "start_component_id": "start-a",
  "steps": [
    {"kind": "transition", "id": "door-a"},
    {"kind": "component", "id": "market-a", "action": {"purpose": "pickup", "cargo_id": 1, "operation": "open"}},
    {"kind": "transition", "id": "door-a"},
    {"kind": "component", "id": "market-b", "action": {"purpose": "pickup", "cargo_id": 2, "operation": "open"}},
    {"kind": "component", "id": "delivery-a", "action": {"purpose": "delivery", "cargo_id": 1, "operation": "unload"}}
  ]
}
```

引用只能来自当前项目。重复物理位置是不同访问，生成的运行时 waypoint ID 必须唯一。
目标动作显式保存为 `pickup`、`delivery` 或 `visit`；`visit` 不带仓控参数。
仓位只允许 1/2，操作只允许 open/close/unload，分别对应已经验证的 0/1/2。
不向 uint8 货舱接口直接传入 -1；不凭注释猜测双仓展开语义。

保存、选择、删除线路均使实验预览失效。修改地图标记后保留线路引用；失效引用须明确报错，
不能悄悄删除任务或替换目标。仅没有 `task_lines` 字段的历史项目保持原编译行为；新项目的
空线路列表、失效选择或失效引用均阻止编译，不能回退到隐式任务。项目原有 single/multi
模式不改写，选中线路的实验预览标识为 fixed。

## 定位与执行边界

定位路线继续负责地图归属、电梯落点和定位文件，跨图顺序不由浏览器提交。
固定任务线路负责业务访问顺序，后端根据相邻任务位置生成必要的地图通行段。
自动切图仅复用当前已批准的实际地图连接和物理电梯；找不到连接、身份不一致或不可达时阻止导出，
不按坐标邻近猜测，不新增运行时节点类型。当前支持同图及同楼栋单元内唯一共享物理电梯的跨图
连接；摆渡层已包含电梯大厅时可省略独立大厅阶段，通过本线路实际访问楼层和共享物理电梯解析唯一楼栋单元，项目全局归属保持不变。其他未批准的户外/摆渡连接明确拒绝。末步为目标点或手动过渡点，设施后须添加明确出口。

编译一次选中的线路，支持切换其他已保存线路后再导出。每份导出包含完整去程与自动返程、
该线路所需的行为树和地图定位清单。各线路不能共享含有不同固定业务参数的同名 XML。
固定线路的电梯目标信息使用已验证的 SetBlackboard 节点写入本线路的确定参数，不能在中途
被另一个动态订单覆盖。沿用现有电梯呼叫、门状态检查、地图切换与定位操作顺序。

返程反向经过实际通行节点；门禁开关动作反向配对、电梯源/目标互换。目标位置可以作为返程
经过点，但仓控动作全部移除。整单完成状态 109 只在最终回到起点时发布一次；取货不能误报
配送到达 701。任务 JSON 与定位清单由同一执行链得到，不分别猜测返程首点。

可达性与最终导出使用同一份 YAML 指定栅格，纳入手动擦除、黑白导出规则和虚拟墙；遵守
negate/free_thresh。同次编译缓存各地图解码结果。预览按业务步骤显示取送货顺序，同时通过
subtask_map_asset_ids 显示全部去返路线，避免展示内部 XML 文件名或跨图误连。

## 验证

覆盖：自动绑定幂等、历史模板编号不变、缺失/冲突归属拒绝；多个取货点、多个送货点、重复
过渡点、独立仓位与操作、去程顺序、返程无仓控、门禁反向动作、电梯地图切换和首返节点；
跨项目引用、删除后悬空引用、空线路、无可用地图连接、同名文件冲突、旧项目编译回归。
浏览器检查保存恢复、切换线路、键盘排序、定位弹窗不再出现、正常/空/错误状态。

共享契约消费者只有 Backend 与 PC Web；Mobile 不消费本编辑流程，不增加移动端依赖。

# 自动派生部署路线与组件执行链设计

**状态：已确认，待实施**\
**日期：2026-09-27**\
**取代：** `2026-09-24-component-execution-chain-design.md` 中要求人工维护路线、锚点或组件顺序的交互。

## 目标

部署实施人员只做两类业务操作：创建项目/场景模型，以及在地图上标记实际设施与核心点位。地图段顺序、切图锚点、去返程端点、组件经过顺序和返程反向均由 Backend 自动推导；Web 仅展示推导结果、证据与可操作的地图修正提示。

`execution_nodes` 仍是项目快照中的有序链表，但它是 Backend 生成的审计结果，绝不再是浏览器提交的人工作业数据。

## 自动事实来源

1. 地图顺序来自创建项目时保存的 `deployment_flow` 和已绑定的地图段，不能在路线页勾选、上移或下移。
2. 起点、目标、电梯、过渡点和区域/设施组件来自地图标记；定位绑定的楼栋、单元和角色是导入地图及场景模型的事实。
3. 对每张地图，Backend 读取已导入 2D 地图的可通行栅格。任务过渡点是必经锚点：服务端按当前可达距离和稳定 ID 自动选择下一个点，再将各锚点间的最短路径拼接为该段路线。
4. 减速区、坡道、窄通道、闸机和自动门投影/相交到该路径，按路径弧长形成唯一链表顺序。返程严格为该有向链的反向投影，保留每种组件的方向、速度和动作语义；减速区的朝向只旋转覆盖矩形，不表示穿越方向。

## 自动路线规则

```text
项目场景地图顺序
  -> 每段的固定起止锚点
  -> 自动排序的任务过渡锚点 + 可通行栅格路径
  -> 路径上的设施排序
  -> 去程执行链
  -> 反向投影的返程执行链
```

- 大厅段的终点和目标层段的起点来自同一条已标记的电梯切图事实；目标层返程应以该段执行链的最后一个路径节点反向返回，而不是重新猜测一个“返程点”。
- 地图上有多个候选起点、目标或电梯，或相邻地图缺少唯一、物理一致的电梯切换事实时，自动派生失败并指出具体地图/标记；不提供人工下拉框兜底。
- 组件不在求得路线附近、多个候选投影无法稳定区分、组件方向与前后路径矛盾、组件越界或路线无法连通时，自动派生失败。错误必须告诉实施人员回到哪张地图调整哪一个标记或设施朝向。
- 支持的组件必须都参与本地图的自动链。当前 profile 无批准执行语义的组件继续阻断导出，绝不静默遗漏。

## UI 与安全边界

- 保留既有“定位运行配置/确认地图经过顺序”的卡片、引导任务和进度轨道，不改变页面总体布局或渐进式任务门控。
- 将路线区域改为只读的“系统自动派生结果”：显示场景地图序列、固定锚点、自动排序的节点、方向、速度和行为树动作。
- 删除或隐藏路线勾选、端点选择、锚点选择、加入末尾、移出、上移、下移等人工控制；也不把这类控制作为可编辑 API 暴露给浏览器。
- 可见异常状态只提供“回到地图标记修复”的原因与入口，不让用户以改顺序绕过路径安全检查。
- 仍仅生成项目工作区实验预览，不安装、不下发、不启动机器人、ROS、定位或 Supervisor。

## 验收与测试

Backend 覆盖场景流程顺序、地图绑定和唯一电梯事实自动生成路线；栅格路径上过渡点及每种支持组件的稳定排序、去返程反转、方向和速度；不连通、离线路径、方向冲突、歧义、遗漏锚点/多电梯均以可操作错误阻断；旧手工 `execution_nodes` 仅作读取兼容资料，自动派生覆盖为当前地图事实；编译器、定位清单和预览使用同一份派生链。

Web 覆盖路线页面不渲染人工排序、端点或地图选择控件；自动派生结果与后端错误有明确状态；项目保存、地图标记后重新打开页面会刷新只读路线结果；并保留单任务、逐步引导的页面门控。

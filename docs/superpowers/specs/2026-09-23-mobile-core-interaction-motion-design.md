# Aletheia Mobile 核心交互动效设计

**日期：** 2026-09-23
**范围：** Flutter Mobile；第一期核心操作反馈。
**不在范围内：** Backend、Web、ROS、HTTP/WS 契约、地图/点云/视频渲染与机器人安全语义。

## 目标

为 Aletheia Mobile 建立一套克制、直接且可维护的交互动效语言。动效必须帮助操作者理解按下、状态改变和表面出现/收回；不得为装饰而动，也不得增加机器人控制、网络请求或实时观测的延迟。

视觉取向为专业、工业化的 Apple 平台体验：输入即时响应，直接操控与手指 1:1 跟随，状态切换可打断，默认无弹跳；只有直接物理操控的摇杆回中保留弹簧。

## 已确认范围

第一期只覆盖下列核心操作：

1. 主操作、次操作和可点击卡片的按压反馈。
2. 连接、保存、错误与受控手动控制状态的表面/状态徽标切换。
3. 对话框、底部弹层和 Snackbar 的空间一致进出场。
4. 手动控制页的可控、回零 STOP、链路延迟和安全锁定反馈。
5. 减少动态效果的替代行为，以及 Debug Gallery 的可审查状态。

以下内容明确不动画：地图、点云、视频帧、遥测数值刷新、高频一级导航切换、网络请求等待和摇杆输入路径。

## 架构

### 统一动效底盘

扩展 `mobile/lib/app/motion/aletheia_motion.dart`，使它成为唯一的动效节奏、曲线和“减少动态效果”策略来源。它只提供 UI 行为，不持有业务状态、不调用 Repository，也不改变 Controller。

| Token | 用途 | 默认行为 | 减少动态效果 |
| --- | --- | --- | --- |
| `press` | 按钮、可点击卡片 | 100–140ms，缩放至 0.97 后回弹 | 100ms 色彩/Ink 响应，不缩放 |
| `state` | 状态芯片、操作表面、保存结果 | 180ms，opacity/color/边框过渡 | 100ms opacity/color |
| `surface` | Dialog、BottomSheet、Snackbar | 240ms，透明度与来源一致的短位移 | 120ms 的平台弹层过渡 |
| `joystickReturn` | 摇杆松手回中 | 现有二维、可打断 Spring | 即时回中或低位移淡化；不影响 STOP |

普通 `state` 和 `surface` 动效使用现有 `AletheiaMotion.easeOut`；不为仪表盘式功能界面引入循环、发光、抖动或大面积位移。`MediaQuery.disableAnimationsOf(context)` 是唯一的减少动态效果判断来源。

动效底盘不能把“正在动画”存入 Controller、Provider 或网络模型。它只接受当前已渲染的局部 UI 状态；这样重复 build、轮询结果和迟到的网络响应都不会启动第二条业务链路。

### 组件边界

新增或抽取的共享 UI 辅助组件仅可完成以下职责：

- 可按压表面：即时按下视觉反馈；释放、取消和禁用时恢复；不拦截业务回调。
- 语义状态切换：用稳定 key 标识连接、保存、锁定或故障状态；只过渡徽标、颜色、边框和局部内容，禁止整页重排。
- 弹层过渡：统一 Dialog、BottomSheet 和 Snackbar 的进入/退出方向，并从触发方向返回。
- 触觉适配器：向 UI 抛出的已确认本地状态变化提供一次性触觉，不读取网络状态，也不参与控制发送。

业务页面保留当前 Controller/Repository/Data Flow。手动控制中的 `/vector`、`/stop`、STOP 有界确认帧、会话释放及安全锁定逻辑一律不改。

第一期只接入已经存在的高价值表面：连接与控制状态芯片、手动控制进入/退出确认、工具页关键卡片、设置保存反馈，以及既有 Dialog/BottomSheet/Snackbar。测试、报告、日志和运行配置页其余列表不会为“统一感”强制添加列表入场或逐项 stagger；那类信息密集页面应保持静止、快速可读。

## 交互规则

### 按压与操作结果

- 触摸按下的同一帧出现 Ink/色彩反馈与 0.97 缩放；不得等待 `onTap` 完成。
- 指针移出后取消按压；业务动作仍只在有效点击时调用一次。
- 保存/提交成功在收到当前操作的成功结果后，状态图标和容器在 180ms 内切换，并触发一次轻触觉。
- 网络失败、超时、权限拒绝或车端拒绝只显示错误状态；不触发成功触觉或成功色。
- 触觉使用 Flutter 平台 `HapticFeedback`；应用以“操作完成事件标识”去重，不以 widget build、动画完成回调或状态轮询触发。

### 状态与安全

- 连接、链路延迟和普通错误只局部切换状态表面，保留当前页面几何和滚动位置。
- 紧急、控制锁定和会话不可用状态必须立即停止动效，切换为稳定的语义错误色，并触发一次警示触觉；禁止闪烁、震动动画或循环提示。
- 摇杆继续 1:1 跟随手指，任何弹簧都从当前显示位置开始并可被新手势中断。松手时先执行现有 STOP 路径，再运行纯视觉回中；视觉效果绝不阻塞 STOP。
- 手动控制的手势面不增加 `GestureDetector` 竞争、不等待触觉 Future、不新增 Timer，也不将控制位置交给 `AnimatedContainer`。它继续由现有直接 pointer 处理器持有手势；回中弹簧仅渲染当前拇指位置。

### 弹层和空间关系

- BottomSheet 从底部出现，并沿底部退出；Dialog 使用短淡入和轻微缩放，不做弹跳。
- Snackbar 从底部安全区域上方出现，并向相同方向退出。
- 路由保留现有策略：一级 HMI 工作区立即切换，二级详情页使用短、低位移的上下文转场。实时观测页面不得套入 `AnimatedSwitcher` 或其他会滞留旧地图/视频帧的容器。

### 触觉

触觉只在动作的语义提交点触发一次：进入/退出手动控制已被接受、摇杆从有效运动回零并开始 STOP、安全锁定、保存成功或失败。普通高频点击、遥测刷新、摇杆移动帧和导航切换不触发触觉。

## 可访问性与性能

- 所有动效尊重 `MediaQuery.disableAnimationsOf`；替代体验保留颜色、文本和短淡入，不删除理解状态所需的反馈。
- 触觉与视觉状态必须在同一状态变更中发出；页面不可因动效而失焦或不可点击。
- 动效只作用于 `opacity`、局部 `transform`、颜色和边框；禁止在高频操作中反复布局、绘制大阴影或创建无界 AnimationController。
- 手动控制、实时观测、地图、视频、点云和遥测路径不增加 debounce、延迟或异步依赖。
- 所有过渡都必须可取消：新的按压、返回操作或安全状态直接从当前显示值接管；不得等待旧动画结束，更不得让旧的“成功”动画覆盖后到达的错误或锁定状态。

## Debug 与验证

Debug Gallery 必须用正式页面/组件覆盖：

1. 已连接的主操作状态。
2. 正在提交与成功/失败状态切换。
3. 手动控制可用、STOP 回零、链路延迟和安全锁定。
4. Dialog、BottomSheet 和 Snackbar 的真实样式。
5. 深色、日光和减少动态效果三种环境。

验证分为四层：

1. Widget 测试：按压取消、状态 key 切换、触觉去重、减少动态效果路径。
2. 手动控制测试：动效不得改变 vector、STOP、STOP 三帧确认、会话释放或锁定时序；拖动路径仍由摇杆独占，页面不可滚动抢占手势。
3. 组件测试以固定时钟断言 0ms 按下反馈、目标时长内的完成状态与中途反向/取消行为；不以肉眼计时测试作为唯一证明。
4. `fvm flutter analyze`、相关 `fvm flutter test` 与 `git diff --check`。
5. iPhone 18 Pro 模拟器：逐项审查深色/日光/减少动态效果；确认实时观测页面仍无地图或视频过渡，并实际拖动摇杆确认无新增输入迟滞。

## 实施顺序

1. 扩展共享 `AletheiaMotion` 和可测试的交互/触觉辅助组件。
2. 先接入不触及控制输入的核心按钮、状态表面与既有弹层过渡。
3. 以独立测试保护后，再接入手动控制的视觉/触觉反馈，保持其安全传输逻辑不变。
4. 添加 Gallery 状态与测试；不得重录或提交现有无关 Golden 失败文件。
5. 在 iPhone 18 Pro 完成三种外观/可访问性环境的审查。

## 风险与边界

最大的风险是把视觉动效误放进手动控制或实时观测的输入/渲染链路，从而造成操作延迟、陈旧帧或错误的安全暗示。实现必须保持“业务先执行、视觉独立跟随”的顺序，并把每个关键安全状态放入 Debug Gallery 和定向测试。

# 组件朝向语义与无箭头符号设计

**状态：已确认，待实施**\
**日期：2026-09-27**

## 背景与根因

当前画布把闸机和自动门的局部 X 轴同时当作“门体横向”和“机器人穿越方向”：浏览器在门图形内绘制 `drawTraversalDirectionArrow`，执行链也以局部 X 两侧生成入口和出口。这一假设与物理设施不符。组件的长边是门面；机器人应从该长边的法线两侧穿过。因此横放的自动门会出现水平箭头，而实际路径应垂直通过。

此问题不能只隐藏箭头：否则画面和生成的开门、通过、关门节点仍会使用错误的物理方向。

## 目标

1. 保持既有部署建图页面、左侧导航、任务卡片、逐步引导和编辑弹窗布局不变。
2. 所有**组件**图标不再使用常驻方向箭头；组件旋转手柄保留，任务过渡点的姿态箭头保留。
3. 闸机和自动门的长边表示物理门面；系统按自动执行链中前后节点决定从法线的哪一侧进入、从另一侧离开，并生成现有的开门—通过—关门动作。
4. 既有地图数据不迁移、不要求重标：已保存的 `yaw` 继续表示组件图形及长边朝向。

## 统一组件规则

| 组件 | `yaw` 的物理含义 | 画布常驻箭头 | 执行链规则 |
| --- | --- | --- | --- |
| 起点、目标点 | 保存机器人姿态 | 无；改为中性圆形锚点 | 固定任务锚点 |
| 电梯 | 门体/门外法线的既有含义 | 无；门体符号和旋转手柄仍在 | 保持已有电梯语义 |
| 闸机、自动门 | 长边为设施门面 | 无 | 沿门面法线生成入口、出口；前后自动路径决定正反侧；入点 `open_go`、出点 `close_go`，返程严格镜像为 `open_back`、`close_back` |
| 窄通道 | 区域长轴 | 无 | 沿长轴进入/离开，侧别由路径自动选择 |
| 减速区、坡道 | 覆盖矩形旋转 | 无 | 由自动路径与旋转矩形的真实边界相交生成速度节点 |
| 任务过渡点 | 去程机器人姿态 | 保留 | 保存 yaw，并对返程镜像 180° |

选择态的缩放框、尺寸手柄和旋转手柄是编辑控件，不属于组件方向标识，继续保留。

## 执行链细节

闸机/自动门的跨越轴取局部 Y（即长边的法线）。实现使用前一自动节点与后一自动节点相对组件中心的投影选择入口侧；两节点必须落在法线的相反侧，否则以“门体没有被路线从两侧穿过”的可操作错误阻断预览。入口、出口的朝向为实际由入口指向出口的航向，而不是组件 yaw。

这只改变设施的空间节点推导，不改变已批准的行为树命名、设备号校验、动作顺序或返程镜像。缺失/非法 `controller_device_id` 仍必须阻断导出，绝不猜测设备号。

## UI 和契约

组件快捷编辑的说明从“按箭头调穿越方向”改为“门体长边表示设施门面，系统按当前自动路径推导穿越侧”。不添加新的步骤、侧栏、手工排序或人工方向开关。共享部署契约同步声明：组件方位用于几何，不再是人为指定的通行正反；任务过渡点仍是唯一显示姿态方向的地图标记。

## 验收与测试

- 横放和竖放的闸机/自动门均从门体法线生成正确入口、出口和航向，正反路径均能生成去返程四个动作节点。
- 同侧掠过门体的路线安全阻断，并指出回到地图调整位置/尺寸，而非让人员调箭头。
- 起点、目标点、闸机、自动门、窄通道、坡道、减速区、电梯的组件符号无内部方向箭头；任务过渡点的姿态箭头仍存在。
- 页面仍使用原有引导式任务门控和布局；不新增手工路线或方向控制。
- Backend、Web 的定向检查通过，并以浏览器实际截图复核自动门、闸机和被动区域。

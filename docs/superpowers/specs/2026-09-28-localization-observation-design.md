# 定位状态与重定位证据设计

## 目标

在 PC 实时运行观测地图右上角显示只读定位健康状态，并在自动测试报告中按运行、按轮次统计重定位次数，在可信地图坐标处标注重定位事件。

## 数据与归因

- Backend 只读订阅 `master_interfaces/msg/LocalizationStatus` 的 `/localization/status`；不调用 `/localizer/relocalize`，不修改 Node Manager、定位或安全链路。
- `state` 映射为：`0` 初始化中、`1` 定位正常、`2` 定位告警、`3` 定位异常、`4` 重定位中。`error_code` 仅在非正常状态翻译为受控中文说明；未知值安全降级为“定位状态需检查”。
- 一次重定位是同一 `fault_id` 首次进入 `state=4`。重复消息不重复计数；到达 `state=1` 后事件标为已恢复。无 `fault_id` 的状态不产生可计数事件。
- 全局监控器保留有界、单调递增序号的事件日志。每轮 `TrajectorySession` 从起始序号读取事件并将其附在下一条已验证的 map 坐标轨迹采样上；没有可信坐标仍保留计数和时间，但不伪造地图位置。

## 界面与报告

- 右上角为紧凑、不可交互的定位状态胶囊，使用当前深色实时地图的半透明石墨表面、细边框和状态色圆点。正常绿、告警琥珀、异常红、重定位中蓝紫、不可用灰；仅重定位中使用克制的状态脉冲，并遵从 `prefers-reduced-motion`。
- 胶囊不显示 `fault_id`、ROS topic 或原始数值；异常时只显示可读原因。地图图层开关、比例尺、诊断条与主轨迹保持原位置。
- HTML/CSV 报告增加运行总次数和每轮次数。SVG 在实际轨迹之上绘制小型蓝紫空心定位标记与独立图例；标记不插入折线、不增粗轨迹，也不劫持既有悬浮采样交互。

## 兼容与验证

- 新增快照端点为增量接口，仅 PC 实时页消费；更新 `shared/contracts/realtime_observation.md`，Mobile 不新增消费者。
- ROS 不可用或状态过期时公开“定位状态暂不可用”，不假定正常。事件监控失败不影响任务执行、轨迹采样或报告生成。
- 定向单元测试覆盖状态归一化、同 fault 去重、每轮归属、无坐标降级、SVG 标记和报告统计；前端测试覆盖状态展示与定时刷新。完成后运行 Backend、Web 检查及一次现场页面视觉核验。

# 机器人日志下载设计

**状态：** 待用户审阅，尚未实现。  
**范围：** 当前小车的系统业务日志下载；不改变 Aletheia 工具日志、ROS、视频、任务、升级或移动端功能。

## 1. 目标与边界

在 PC 浏览器中提供独立的“机器人日志下载”页面，供维护人员从当前打开 Aletheia 的机器人下载系统业务日志。下载文件最终由浏览器保存到打开网页的维护电脑；机器人只在归档过程中使用短生命周期临时文件。

本功能与现有“工具日志”严格分离：

- **工具日志**：仅 Aletheia 自身的控制台、点云、位姿、视频等受控诊断文件；既有接口和页面不改动。
- **机器人日志下载**：仅当前小车上维护人员配置的系统业务日志；不混入 Aletheia 自身日志。

不实现 SSH、SFTP、机器人地址、用户名、密码、私钥、跨机器人连接、无约束的任意路径读取或任意文件读取。Aletheia 已运行于目标小车，这些能力没有必要且会扩大安全边界。

第一版是 Desktop Web 功能；Mobile 不是 Existing 消费者，不修改 Flutter 客户端。

## 2. 日志源与权限模型

后端保存可由授权维护人员在网页中管理的“名称 + 本机目录”日志源。初始默认值为：

| ID | 页面名称 | 根目录 |
| --- | --- | --- |
| `drivers` | drivers | `/opt/ry/Log/supervisor-logs/stdout/today/drivers` |
| `modules` | modules | `/opt/ry/Log/supervisor-logs/stdout/today/modules` |
| `lightning` | lightning | `/opt/ry/workspace/lightning_logs` |

目录配置作为 `console.json` 的 `robot_logs.sources` 字段持久化；每项含后端生成且稳定的 ID、非空显示名称和绝对路径。允许配置任意可读的绝对日志目录，但拒绝 `/`、`/etc`、`/proc`、`/sys`、`/dev`、`/run` 及任何用户 SSH 私钥目录或其子目录。配置本身是维护动作，不等同于给下载 API 开放任意路径。

每个源独立探测目录存在性、可读性和文件数量。运行账户没有权限或目录不存在时，该源显示“不可读”及可操作的原因；其他源仍可下载。普通文件清单不暴露机器人绝对路径；目录编辑表单仅对已保存日志源显示其配置值。

后端只接受日志源 ID 和经清单产生的文件 ID，绝不接受原始路径。每个候选文件都必须：

1. 是该源根目录的普通文件；
2. `resolve()` 后仍位于该根目录内；
3. 不是符号链接；
4. 未超过单文件大小上限；
5. 在请求打包时重新验证以上条件。

目录不存在、权限拒绝、异常文件或超过限制均记录到 Aletheia 工具日志，供排障使用；它们不自动改变机器人系统或执行 sudo。

## 3. API 与数据流

新增 Desktop-only HTTP API 家族 `/api/robot-logs`：

```text
GET  /api/robot-logs/sources
PUT  /api/robot-logs/sources
GET  /api/robot-logs/sources/{source_id}/files
POST /api/robot-logs/archive
```

`sources` 返回已保存源的显示名称、可读状态和目录配置；`PUT` 仅接受完整、经过验证的名称 + 目录列表，新增项的 ID 由后端生成，已有项必须保留其稳定 ID。`files` 返回受控文件 ID、显示文件名、大小和修改时间，可接收关键词参数以筛选文件名；它不读取或扫描日志正文。归档请求和普通文件清单响应均不含绝对路径。

`archive` 接收一个源 ID 与来自该源清单的文件 ID 数组。后端重新校验每个文件，流式写入临时 ZIP，响应使用 `Content-Disposition: attachment` 使浏览器下载到维护电脑。临时文件在完成、客户端中断或异常时都必须删除；不将 ZIP 存入 `reports/`、`logs/`、`updates/` 或用户配置目录。

初版不提供单个原始文件直连下载，统一以 ZIP 下载，便于多选、避免在 URL 中表达文件名、并保持一个下载安全路径。

## 4. 资源与安全限制

归档采用明确上限，防止现场大日志拖慢小车或耗尽磁盘：

- 单文件最大 256 MiB、单次最多 100 个文件、单次源文件总量最大 512 MiB，且同一时刻仅允许一个归档；
- 超限请求在创建归档前拒绝，返回哪个限制触发；
- 不递归目录、不跟随符号链接、不执行 shell 命令；
- 只在受控临时目录创建 ZIP，文件名由后端生成；
- 下载异常、短写或临时文件清理失败记录结构化错误日志。

文件列表按修改时间降序，读取元数据时容忍文件在扫描后被轮转或删除；归档时若文件已消失则明确报告并不打包替代文件。

## 5. 页面与交互

新增 `/robot-logs.html`，在桌面侧栏以“机器人日志”独立入口显示。

页面按源分区展示：

1. 顶部说明当前页只下载当前小车的已配置系统业务日志；
2. “目录管理”允许添加、编辑和删除名称 + 本机目录，并说明禁止系统敏感目录；
3. 分类卡片显示可用、不可读或目录不存在状态；
4. 选中可用分类后加载表格，支持按文件名关键字筛选、全选和多选；
5. 显示已选数量及累计大小，按钮为“下载选中日志（ZIP）”；
6. 归档中禁用重复提交，完成后由浏览器接收下载；失败时保留选择并提示可恢复动作。

页面不显示 SSH、SFTP、主机、账号、密码或私钥。仅“目录管理”表单展示已保存日志源的本机目录，并只允许维护人员提交受后端安全校验的目录；文件清单和下载响应不回显任何绝对路径。它延续现有桌面控制台样式与键盘可达性，且不改动“工具日志”页面。

## 6. 测试与验证

实施前以测试驱动完成至少以下验证：

- 默认日志源与自定义日志源的持久化、唯一 ID、空值、相对路径和敏感目录校验；
- 每个已保存源的状态：可读、目录缺失、权限拒绝；
- 路径逃逸、符号链接、目录、超大文件、轮转后文件消失全部被拒绝；
- 清单不暴露绝对路径；
- 合法多选归档内容、文件名和下载响应正确；
- 超出单文件/总大小/文件数限制时不创建归档；
- 成功、异常和客户端中断后的临时文件清理；
- 现有 `/api/tool-logs/*`、工具日志下载与报告下载回归不变；
- 后端测试与 Web 生产构建通过。

实车验收还需确认 `ry` 账户对每个已配置目录（默认包括 drivers、modules 与 lightning）的读取权限。若权限不足，应通过机器人系统既有部署权限配置授予只读访问，不能在网页中引入密码、sudo 或临时提权。

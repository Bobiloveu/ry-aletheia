# 部署建图渐进式工作台设计

## 目标与使用场景

部署建图是现场实施人员在车辆、地图和路线尚未准备好时使用的操作工具。用户需要明确知道当前只该做哪一件事、为什么还不能进入下一步，以及导入文件是否完整。成功标准是：打开页面后能按顺序完成项目、地图、标记、定位路线和预览；当前阶段只有相关工具可见，已经完成的阶段可以回看，未到达的阶段不会抢占注意力或误操作。

## 设计方向

采用现有 RY Aletheia 深色控制台的 Operate 风格，保留蓝色主操作色、绿色完成色、橙色提醒色和高对比地图画布。页面结构从“多列卡片墙”改为“阶段轨道 + 单一工作台”：顶部显示阶段状态，中央只显示当前阶段的操作区，右侧显示本阶段的事实和校验结果。完成状态以摘要行保留，不再把全部表单继续铺在页面上。

```text
┌────────────── 阶段轨道：项目  地图  标记  定位  预览 ──────────────┐
│ 当前阶段说明                         已完成事实 / 阻塞原因      │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  当前阶段工作台（导入、地图画布或路线编辑，仅显示一个主任务）     │
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│ 已完成阶段摘要        返回编辑       下一步：继续                  │
└──────────────────────────────────────────────────────────────────┘
```

地图导入工作台使用三段交互：选择文件 → 文件清单校验 → 导入快照。清单明确显示 YAML、PGM、PCD 数量和可选的兼容性 `index.txt`；任意命名的非空 `.pcd` 满足定位点云输入，`index.txt` 只在存在时原样保留。错误直接显示在清单下方，并指出需要重新选择哪一类文件。

## 页面状态与交互

`deriveDeploymentWorkflow` 继续作为唯一阶段事实来源。页面增加一个本地的 `viewedStage`，只决定用户正在回看的已完成阶段，不改变服务端事实和下一步判断。首次打开或事实变化时回到 `current`；点击已完成阶段时只显示该阶段工作台；点击锁定阶段时不导航，只聚焦当前阶段并说明前置条件。

工作台显示规则如下：

1. 项目阶段显示项目创建、场景模型确认和项目列表；场景确认后进入地图阶段。
2. 地图阶段显示导入/车端建图、地图阶段绑定、地图资产和拓扑校验；未完成阶段绑定时不展示组件标记和定位路线表单。
3. 标记阶段显示地图画布、组件工具和协议模板；画布仍可切换地图，但其它阶段表单收起。
4. 定位阶段显示定位绑定与路线编辑。若拓扑校验阻塞，地图画布作为衔接点选择工具临时加入本阶段，并将主操作改为“补齐地图衔接”。
5. 预览阶段只显示任务编译预览、服务端错误和下载操作。

当前阶段工作台使用 `data-deployment-stage` 和 `data-deployment-stages` 控制显隐；每个现有 DOM id 保持不变，避免破坏已有事件监听和 API 请求。完成阶段的摘要由向导栏显示，用户点击摘要即可回看，不复制第二份表单。

## 文件与校验边界

浏览器继续上传用户选中的文件，不读取机器人原目录。导入前在浏览器侧检查：恰好一个 YAML、至少一个 PGM 或 YAML 引用的图像、定位地图可选任意命名的 PCD，`index.txt` 可选。服务端仍负责受控目录、YAML 元数据、文件大小和点云内容校验。定位导出只要求至少一个有效 PCD；存在 `index.txt` 时原样打包，不存在时不生成占位文件。

## 可访问性与响应式

阶段按钮使用真实 `button`，当前步骤带 `aria-current="step"`，锁定步骤带 `disabled`；工作台切换后把焦点放到标题或第一个可操作控件。错误信息使用 `aria-live="polite"`。桌面端采用左侧阶段轨道与主工作台，窄屏时阶段轨道变为横向滚动，工作台单列，地图工具栏允许换行。动画只用于工作台切换的短暂状态提示，尊重 `prefers-reduced-motion`。

## 保持不变的范围

不改变部署建图 URL、后端 API、地图编辑坐标、组件属性格式、定位路线数据结构、实验包下载边界或车端运行时。只重构前端工作台编排、导入校验反馈、可选 `index.txt` 的文案和定位导出对可选兼容文件的处理。

## 验证标准

- 无项目、地图准备、标记、定位阻塞、预览错误和预览成功六种状态下只显示对应工作台。
- 导入文件清单能区分 YAML、PGM、任意命名 PCD 和可选 index，并在缺失时给出明确恢复动作。
- 既有地图画布、组件编辑、路线编辑和下载按钮的 DOM id 与请求路径不变。
- 前端单元测试、完整 `scripts/test-web.sh`、Python 定位清单测试通过。
- 使用 agent-browser 检查桌面和窄屏首屏，确认没有横向溢出、锁定步骤可见但不可操作、导入反馈和当前工作台标题清晰。

# 实时观测：手动地图标记与受控前往设计

**日期：** 2026-09-30\
**状态：** 已确认，待按实现计划落地

## 1. 背景与目标

实时观测页此前会扫描任务目录、解析任务文件，并从匹配当前地图的任务中推导起点和终点。任务文件数量增加后，该流程既慢又不可控；任务文件的变动也不应影响实时观测的交互延迟。

本次改造将该能力替换为由操作员维护的**手动地图标记**：在当前已验证显示的地图上输入坐标和航向，命名后保存为该地图的标记；右键标记可在原有安全边界内发起“前往”。

目标：

- 完全停止读取、遍历或解析任务目录来获得实时页标记。
- 标记只属于创建时已严格验证的当前地图；切换到其他地图时绝不显示。
- 操作员可输入 `alias`、`x`、`y`、`yaw`（弧度）创建标记，且可删除。
- 右键标记可发起受控 Nav2 前往；保留当前所有任务互斥、控制权、定位、急停和二次地图校验。
- 标记持久化在工具自身配置中，不写机器人任务文件，不暴露地图路径给浏览器。
- 实时图层不再有任务文件扫描或轮询开销；只有已确认地图成功加载、创建、删除或用户重新启用图层时才读取标记。

非目标：

- 不导入或同步机器人任务文件。
- 不替代测试任务、任务执行器、定位、Nav2 或安全控制系统。
- 不在移动端加入创建或前往控制；移动端仍是只读观测。
- 不自动执行、自动选择或自动前往任何标记。

## 2. 地图绑定与持久化模型

新增后端模块 `autodrive_console/manual_map_markers.py`，负责校验、读写和按地图筛选标记。它不依赖 `task_directory`、多任务目录或任何任务 JSON。

文件位于工具受控配置目录：`config/live_map_markers.json`。采用版本化、原子写入的 JSON：

```json
{
  "schema": 1,
  "markers": [
    {
      "id": "opaque-random-id",
      "map_id": "server-only-map-asset-id",
      "alias": "电梯厅待命点",
      "x": 12.4,
      "y": -5.8,
      "yaw": 1.5707963268
    }
  ]
}
```

`map_id` 是 `ObservationManager` 在**已完成 map_server YAML 与 OccupancyGrid 严格匹配**后取得的稳定内部地图资产 ID。它不是地图路径，永不返回浏览器，也不从请求体接收。若当前地图没有完成该验证，后端不允许列出、创建、删除或前往标记。

同一 `map_id` 的标记最多 500 个；超过上限时创建请求失败并提示先删除不再使用的标记。标记 ID 使用不可预测的随机值。别名去除首尾空白后长度为 1–48 个 Unicode 字符；`x`、`y` 必须为有限数且绝对值不超过 100,000 米；`yaw` 必须是有限数、绝对值不超过 10,000 弧度，保存时规范化为 `[-π, π)`。配置载入时跳过无效、损坏或超界的记录，保留其他有效记录；首次保存前自动创建空文档。

写入使用临时文件、`fsync` 与原子替换，权限沿用工具配置的现有安全约束。文件中只保存操作员输入的名称与坐标、内部地图 ID，不保存任务路径、ROS 命令、用户凭据或地图内容。

## 3. 后端接口

旧的 `current_map_task_points.py`、任务目录扫描索引、`task-points` 接口和“任务起终点”语义全部删除。`TaskStartNavigationController` 改为基于 `ManualMapMarkerStore` 解析标记，并改名为 `MapMarkerNavigationController`，避免保留“任务起点”的误导。

### 3.1 标记接口

所有接口都仅供 PC 实时观测页使用，并且必须先取得当前严格验证的内部地图 ID。

| 方法与路径 | 请求 | 成功响应 | 约束 |
| --- | --- | --- | --- |
| `GET /api/observation/map-markers` | 无 | `{ "map_ready": true, "points": [{"id","alias","x","y","yaw"}] }` | 当前地图未验证时返回 `map_ready: false` 和空数组。响应不含 `map_id` 或路径。 |
| `POST /api/observation/map-markers` | `{ "alias": string, "x": number, "y": number, "yaw": number }` | `{ "ok": true, "point": {"id","alias","x","y","yaw"} }` | 请求键必须恰好匹配；后端绑定当前地图，不能由浏览器指定。 |
| `POST /api/observation/map-markers/remove` | `{ "id": string }` | `{ "ok": true }` | 只能删除当前已验证地图拥有的标记；其他地图或不存在 ID 返回安全失败。 |

请求体上限 16 KiB。输入不是 JSON 对象、字段缺失/多余、类型不符、越界或当前地图未验证时，响应为明确但不泄露内部路径的 4xx 错误。每次创建和删除写入工具日志，日志只记操作结果和标记 ID，不记坐标或地图路径。

### 3.2 受控前往接口

导航状态与动作改为以下新路径，旧 `task-point-navigation` 路径删除：

| 方法与路径 | 请求 | 含义 |
| --- | --- | --- |
| `GET /api/observation/map-marker-navigation` | 无 | 返回受控前往的空闲/进行中/成功/失败/取消状态，不含内部地图路径。 |
| `POST /api/observation/map-marker-navigation/begin` | `{ "id": string }` | 请求前往当前已验证地图中的一个手动标记。 |
| `POST /api/observation/map-marker-navigation/cancel` | `{}` | 请求取消正在执行的该次导航。 |

前端只能提交标记 ID，坐标和地图绑定均由后端的已保存标记决定。发起请求和实际向 Nav2 发送目标前都重新解析当前地图 ID 与标记归属；地图切换、标记删除或验证失效会使请求失败，而不会向错误地图发目标。

## 4. 导航与安全边界

地图标记只是目标选择方式的替换，不放宽任何已有的驾驶控制规则。`MapMarkerNavigationController` 必须在开始及发送 ROS 目标前再次检查：

1. 没有活动的自动测试或验收运行。
2. 车辆实际控制源是 `navigation`，且不存在控制权切换、手动控制会话或手动重定位流程。
3. 急停状态正常，定位服务可用且定位状态正常。
4. 实时观测的当前地图已通过 map_server YAML 与 OccupancyGrid 的严格匹配。
5. 标记仍属于该当前地图。
6. Nav2 `NavigateToPose` action server 可用。

成功时仅向既有 `/navigate_to_pose` action 发送保存的 `x/y/yaw` 目标；不修改任务文件、地图、定位参数、Supervisor 或控制模式。失败、超时、取消、地图变化或 Action 结果异常都保持/恢复现有安全状态并将原因记入工具日志。最大导航时长与已有受控前往一致（300 秒）；取消失败同样必须可见于状态和日志。

## 5. PC 实时观测交互

图层面板把“任务起终点”改为“地图标记”。关闭时仅隐藏渲染，已保存的标记和导航状态不受影响。图层打开时在当前已验证地图成功加载后请求一次标记；不会周期性请求标记，更不会扫描文件。

地图右上/左上现有紧凑控件区域增加低强调度的“添加标记”按钮。点击后显示紧凑浮层表单：

- 名称（别名）
- X（米）
- Y（米）
- 朝向 yaw（弧度）
- “保存标记”与“取消”

表单不预填当前位置，也不发送任何导航；保存成功后立即刷新当前地图的标记层。错误应在浮层中说明，例如“当前地图尚未确认”或“坐标格式无效”。视觉沿用实时观测的克制半透明面板、圆角、细边框和系统层级，不增加大面积常驻卡片或抢占地图操作。

每个标记使用与虚拟墙、点云明显区分的低干扰图标。常规缩放下不永久铺满别名文本，避免密集地图遮挡；右键命中时弹出上下文菜单，显示别名并提供：

- `前往此标记`：只有后端安全状态允许时才开始，进行中显示取消入口与当前状态。
- `删除标记`：经一次明确确认后删除当前地图标记。

鼠标左键拖图、缩放、右键空白处、地图切换和浮层关闭时均关闭上下文菜单。标记只按当前地图数组渲染；切换地图先清空旧标记，待新地图严格确认后再加载，因此不会短暂把旧图标显示在新地图上。

## 6. 迁移、契约与测试

旧的任务扫描索引是未持久化实时派生态，删除后不做数据迁移；升级后的“地图标记”初始为空，操作员按需创建。删除内容包括：

- `autodrive_console/current_map_task_points.py` 和对应测试。
- 通过任务目录/多任务目录发现点位的代码、缓存、接口与前端轮询。
- “任务起点”“任务终点”“前往任务起点”文案及图层名。

保留且调整为手动标记实现的内容包括：Nav2 action 传输、运行互斥、车辆控制/重定位/定位/急停校验、取消、超时、状态展示及工具日志。

`shared/contracts/realtime_observation.md` 更新为手动标记 API、地图绑定、PC-only 消费者、无路径泄露和无任务目录扫描；`shared/contracts/robot_control.md` 与 `shared/contracts/task_execution.md` 将相关术语改为“受控地图标记前往”，明确它不属于任务执行也不能与任务运行并行。消费者影响记录注明 Backend 与 PC Web 已同步，Mobile 无该接口消费者。

最小自动化验证覆盖：

1. 标记配置的载入、空配置、原子保存、校验、yaw 规范化、容量限制和按地图隔离。
2. API 只在严格验证当前地图后列出/创建/删除；请求不接受 `map_id` 或路径，切图不会返回旧标记。
3. 控制器在开始和发送 Nav2 前二次校验地图与安全状态，且绝不解析任务目录。
4. 前端静态与行为测试覆盖图层名称、非轮询刷新、添加表单、右键菜单、删除确认和旧任务点 API 的移除。
5. `scripts/test-backend.sh`、`scripts/test-web.sh` 与 `git diff --check`。

不将“代码测试通过”描述为实车导航验证；实际发送导航目标仍需由操作员在空闲、安全地图上执行现场确认。

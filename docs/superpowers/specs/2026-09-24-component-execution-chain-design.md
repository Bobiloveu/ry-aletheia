## 1. 问题与目标

部署画布会为起点、目标、电梯、闸机、自动门、窄通道、坡道和减速区保存组件及内部编辑 Waypoint。当前 `indoor_elevator_v1` 编译器仅消费起点、目标、电梯和手动 `transition`。结果是减速区等组件虽然可配置，最终任务 JSON 却静默遗漏其语义。

目标是让每个组件在任务预览中拥有唯一、可追溯的结论：

- 已编译为导航路径段或行为树动作；或
- 因当前实验 profile 没有批准语义而以可操作错误阻断预览。

禁止静默忽略任何被纳入当前任务地图的组件，也禁止按创建时间、坐标近邻或地图图形猜测机器人实际路线。

## 2. 不变安全边界

- 继续只生成项目工作区内的实验预览、ZIP、任务 JSON、受控 XML 与定位 YAML；不安装、不下发、不启动 ROS、Supervisor、导航或定位。
- 浏览器只提交项目意图，Backend 是顺序、设备号、模板渲染、路径校验和产物写入的唯一权威方。
- 继续复用已有、批准的速度模式：`task_point`、`single_point`、`slow_point`、`narrow_point`、`elevator_in`、`backward`；不创建速度模式 XML。
- Mobile 不是部署编辑或实验导出的消费者，不增加 Mobile API。
- 两图、单电梯、单起点、单目标往返仍是当前唯一可生成的任务 profile。室外、摆渡、楼栋入口等不能由该 profile 表达的组件必须失败说明，而非伪造动作。

## 3. 任务执行链

每个参与编译的地图段维护一个显式、有序的 `execution_nodes` 列表。节点引用一个手动过渡点或一个组件 ID，且同一节点在同一地图段只出现一次。

固定锚点不由用户排序：

```text
大厅去程：起点 → [execution_nodes] → 候梯点 → 电梯中心
目标层去程：出梯/候梯点 → [execution_nodes] → 目标点
目标层返程：reverse(execution_nodes) → 候梯点 → 电梯中心
大厅返程：候梯点 → reverse(execution_nodes) → 起点
```

Web 在“本地图任务路径顺序”中展示所有可加入节点、固定端点、未编排项和阻断原因。实施人员通过加入、移除、上移、下移或拖动确定真实经过顺序。旧项目若没有非固定组件或手动过渡点，使用空链保持兼容；存在未编排项时不得预览或下载。

`execution_nodes` 存入当前 `localization_route`，因为它已拥有唯一楼栋/单元和有序地图绑定。每个 binding 恰有一个条目，条目只含 `binding_id` 与不重复的节点引用；Backend 校验引用地图归属、类型、完整性与唯一性。

## 4. 以路径段而非点定义速度

`speed_mode` 的正式语义是“到达当前输出 waypoint 前的这一段运动策略”。因此编译器内部先构建有向**路径段**，再分别投影为去程与返程路点，不能简单倒序复制点的 `speed_mode`。

对任一去程边 `A → B`，其模式保存在去程 `B`；返程相同物理边 `B → A` 的模式保存在返程 `A`。这保证减速和窄通道在两个方向都落在同一物理区间，且不会发生速度错位。

### 4.1 速度区域组件

`slow_zone`、`ramp`、`narrow_passage` 都是沿组件局部 X 轴通过的有方向区间：

- Backend 根据组件中心、`yaw`、`width_m` 计算入口和出口；入口/出口必须在所属地图边界内；
- 去程沿组件正向时为 `entry → exit`，反向经过时交换；
- 区间内分别使用组件配置的 `slow_point` 或 `narrow_point`；区域外的下一段恢复由后续节点自身决定的速度；
- 生成点必须保留 `generated_by`、组件 ID、`entry/exit` 角色和几何来源，供预览、输入指纹和追溯使用；
- 无法在当前显式链中确定从哪一侧进入时，预览阻断并要求实施人员修正顺序或组件朝向。

区域不运行行为树，输出的对应 waypoint `waypoint_task_id` 为空且 `is_task_point` 为 `false`。

## 5. 闸机与自动门动作

闸机和自动门是有方向的穿越组件。每个组件拥有显示编号（例如 `G-01`、`D-01`）以及必填的纯数字 `controller_device_id`。后者是 `DoorControl doorid` 的唯一来源；显示编号绝不被解析为设备号。

每次穿越会派生入口动作点与出口动作点：

| 行驶方向 | 入口动作 | 出口动作 |
| --- | --- | --- |
| 去程 | `open_go` | `close_go` |
| 返程 | `open_back` | `close_back` |

动作点的路线位置由组件局部 X 轴、尺寸和受控安全偏移派生；所有点必须处于所属地图。打开动作发生在穿越前，关闭动作只发生在确认经过后的出口点。

模板来源是用户提供的参考行为树：

- 闸机：`e_guard_open_go.xml`、`e_guard_close_go.xml`、`e_guard_open_back.xml`、`e_guard_close_back.xml`；
- 自动门：`*_open_door_go.xml`、`*_close_door_go.xml`、`*_open_door_back.xml`、`*_close_door_back.xml`。

这些仅作为动作顺序参考。项目内会建立版本化、参数化的受控模板，不复制其写死的现场地图路径、定位 YAML、重定位坐标或设备号。模板只允许替换经过数值验证的 `controller_device_id`、受控动作名称和批准的任务上下文；所有 XML 值必须转义。每个输出 XML 的文件名由项目内稳定组件 ID 和方向/动作确定，不能由用户填写路径或任意文件名。

动作点以 `is_task_point: true` 输出并引用生成的 XML。模板缺失、设备号非正整数、动作点越界或组件顺序不完整时，预览必须以 `422` 阻断。

## 6. 组件分类和预检

| 组件 | 执行结果 |
| --- | --- |
| `start`、`target`、`elevator` | 当前 profile 的固定受控锚点/电梯行为树；不可在中间链重复加入。 |
| `transition` | 用户控制的纯导航节点，可设置速度和朝向。 |
| `slow_zone`、`ramp`、`narrow_passage` | 生成有向区间路径点及相应速度段。 |
| `gate`、`auto_door` | 生成去返程开/关动作点和受控 XML。 |
| `building_entrance` | 当前 profile 无动作语义；只要参与地图存在该组件即明确阻断。 |

同一地图上所有非固定组件和所有手动任务过渡点必须被执行链收录。组件有重复引用、遗漏、错误地图、跨图引用、与固定锚点冲突或几何越界时，预检必须说明组件名称、地图和恢复操作。

## 7. 兼容、预览和契约

- 旧项目读取后，在不存在可执行中间项时保持原任务 JSON；存在项但没有 `execution_nodes` 时标记“待编排”，不猜测顺序。
- 修改组件几何、属性、设备号、执行顺序、过渡点坐标/朝向/速度、地图绑定或任务锚点，统一使实验预览失效。
- 预览显示每个子任务的最终节点顺序、节点来源、入站速度、行为树文件、设备号（脱离人可读显示编号）与去返程对应关系。
- `shared/contracts/deployment.md` 更新 Existing 的定位路线/任务路径对象、组件设备号和编译行为；现有 PC Web 与 Backend 为消费者，Mobile 仍非消费者。
- 产物清单记录执行链、派生路径段、模板版本和 SHA-256，使 JSON/XML 可追溯到项目组件。

## 9. 验收与测试

Backend 必须覆盖：

- 每一种组件的正确生成或明确阻断；
- 显式执行顺序、遗漏/重复/跨图/固定锚点冲突；
- 减速区、坡道、窄通道的正向和逆向几何、速度段与地图边界；
- 去返程每一条物理路径段使用相同速度模式，且模式不发生错位；
- 闸机和自动门的 `open_go → close_go`、`open_back → close_back` 顺序，纯数字设备号、XML 转义、模板安全和任务 JSON 引用；
- 旧项目兼容、预览失效、输入散列和 ZIP 内 JSON/XML/清单一致。

Web 必须覆盖：

- 每张地图的执行链编辑、可读节点名称和键盘/拖动排序；
- 未编排与不支持组件的阻断提示；
- 设备显示编号和控制设备编号不重复误导；
- 预览中显示去返程路径段、速度、动作和来源；
- 窄屏、桌面、深浅色主题下的可读性及不溢出。

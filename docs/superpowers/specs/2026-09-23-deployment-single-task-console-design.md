# 部署建图单一任务指挥台设计

## 背景

现有部署建图页面已经具备五阶段向导，也能从项目、拓扑与预览事实推导当前阶段和下一操作。但阶段内仍同时铺开导入、建图、画布、地图阶段、组件和定位路线等多个区域。新手需要在左右栏之间判断先后顺序，页面虽然“功能完整”，却没有把唯一的当前任务落实到布局和操作层。

本设计延续 [部署建图渐进式工作台设计](2026-09-19-deployment-wizard-redesign-design.md) 的五阶段事实模型，并进一步把每个阶段拆成顺序明确的单一任务。它不建立第二套业务状态，不改变 Backend、API、ROS、地图数据或实验导出契约。

## 目标

- 用户打开页面后无需理解页面分栏，立即知道当前只需完成哪一件事。
- 每个页面状态只有一个主操作；完成后系统明确说明结果并进入下一任务。
- 地图按“选择来源 → 导入或建图 → 命名并检查 → 绑定地图阶段 → 确认”逐张闭环，而不是先导入所有地图再回头补属性。
- 已完成阶段默认只读回看；修改前明确告知受影响的后续阶段。
- 错误、超时或校验失败不会误推进，用户输入和最后成功状态可恢复。
- 在 1366、1600、1920 宽度及浏览器 200% 缩放下保持可读，不再以缩小文字换取一屏容纳全部功能。

## 非目标

- 不改变 `/api/deployments`、`/api/mapping` 或任务编译接口。
- 不改变 `SiteProject`、`deployment_flow`、地图资产、组件、定位绑定或定位路线的数据结构。
- 不新增浏览器直接写机器人目录、调用 ROS 或控制 Supervisor 的能力。
- 不把前端进度视为权威事实；Backend 返回的项目快照和校验结果仍是唯一事实来源。
- 不修改 Mobile。该部署编辑能力仍只属于 PC Web。

## 设计原则

### 单一任务

页面只把当前任务呈现为可操作区域。顶部显示全局五阶段，主区域显示当前任务与完成标准，右侧只显示只读进度。与当前任务无关的表单不以禁用卡片或第二栏入口继续占据页面。

### 服务端事实优先

`deriveDeploymentWorkflow(project, topology, preview)` 继续推导五个全局阶段。新增的阶段内任务推导必须同样是纯函数，只读取项目、拓扑、建图会话、预览和当前未提交草稿，不持久化一份平行状态机。

### 安全操作自动推进

导入成功、名称保存、阶段绑定等普通且可恢复的操作，在服务端成功响应并重新获取权威事实后自动进入下一任务。页面保留一条成功回执，说明刚完成的动作和当前已进入的任务。

导出、删除、回退已完成阶段，以及任何会影响交付成果的操作仍要求明确确认。

### 回看不产生副作用

点击已完成阶段只改变本地 `viewedStage`，不发保存请求、不重新计算项目、不改变当前阶段。只有用户点击“修改此步骤”、确认影响范围并实际保存修改后，工作流才根据新的服务端事实重新推导。

## 信息架构

桌面页面使用四层结构：

1. 项目栏：项目名称、保存状态和当前工作区身份。
2. 全局阶段轨：创建项目、准备地图、标记地图、配置定位路线、校验并导出。
3. 单一任务区：当前任务说明、完成标准、唯一主操作和完成该任务所需的工作区。
4. 只读进度栏：本阶段子任务进度和已完成事实，不提供第二条编辑路径。

```text
┌─ 项目名称 ────────────────────────────── 保存状态 ─┐
├─ 创建项目 ─ 准备地图 ─ 标记地图 ─ 定位路线 ─ 导出 ┤
│ ┌─ 当前任务、完成标准 ──────────────── 主操作 ┐ │
│ └────────────────────────────────────────────┘ │
│ ┌─ 当前任务工作区 ─────────────────┐ ┌─进度─┐ │
│ │ 仅显示完成本任务需要的输入或画布   │ │只读  │ │
│ └──────────────────────────────────┘ └──────┘ │
│ 成功后将进入的下一任务                              │
└───────────────────────────────────────────────────┘
```

工作台最大宽度为约 1480px，并在更宽视口中居中。正文不低于 14px，真正次要的元信息不低于 11px。右栏约 292px；当前任务区占据剩余空间。空画布不为“填满屏幕”而无限增高。

窄于 1040px 时进度栏移到主工作区下方；窄于 760px 时任务说明、操作区和表单改为单列，全局阶段轨允许横向滚动。DOM 顺序与视觉顺序一致。

## 全局阶段与阶段内任务

### 全局阶段

保留现有顺序与语义：

1. `project`：创建项目并配置部署流程。
2. `maps`：逐张准备和绑定地图。
3. `annotations`：逐张完成航点和组件标记。
4. `localization`：配置地图运行角色与有序定位路线。
5. `export`：保存小区身份、生成服务端预览并下载实验包。

锁定阶段可见但不可进入；已完成阶段可只读回看；当前阶段是唯一默认入口。

### 地图阶段

每张地图按以下子任务闭环：

1. 选择地图来源：导入已有地图或准备车端建图会话。
2. 导入或建图：完成文件校验或保存车端建图结果。
3. 命名并检查：填写现场可识别名称，展示地图类型、文件组合、尺寸和校验状态。
4. 绑定地图阶段：绑定到 `deployment_flow` 中当前未完成的阶段。
5. 确认当前地图：展示保存结果并自动转向下一未完成地图阶段；全部阶段绑定完成后进入标记阶段。

第 5 步是保存成功后的结果确认，不新增持久化字段或额外确认 API。它用于让用户明确本张地图已经闭环，并说明系统接下来处理哪张地图。

阶段内任务由新的纯推导函数生成，例如 `deriveDeploymentTask(workflow, project, topology, mappingSession, draft)`。返回值至少包含：

- `stageId`：所属全局阶段。
- `taskId`：稳定的阶段内任务标识。
- `title`、`detail` 和 `completionCriterion`。
- `primaryAction`：当前唯一主操作及目标。
- `nextTaskLabel`：成功后进入的任务。
- `progressItems`：右栏只读子任务列表。
- 可选 `targetMapId` 或 `targetStageId`，用于选择正确地图，不作为服务端事实。

现有 `ACTIONS` 可扩展为阶段内动作，但同一状态只返回一个主操作。

## 交互与状态流转

### 普通成功

1. 用户触发当前主操作。
2. 页面禁用该按钮并显示具体的进行中状态，防止重复提交。
3. Backend 成功返回项目或会话事实。
4. 页面刷新项目、拓扑和预览数据。
5. 纯推导函数计算新的当前任务。
6. 页面显示成功回执并将焦点移动到新任务标题或首个输入。

前端不能在请求成功前预先把步骤标记为完成。

### 校验失败、请求失败或超时

- 停留在当前任务，不自动推进。
- 在当前任务卡或对应输入附近说明具体原因和恢复方式。
- 保留用户已选择的来源和可安全保留的表单输入。
- 恢复主按钮并允许重试。
- 不修改全局阶段完成状态。

页面刷新后以服务端最后一次成功保存的事实为准。未提交草稿可继续使用现有会话状态机制保存，但不能把草稿伪装成已完成状态。

### 重复提交

请求进行期间禁用主操作。同一动作的事件入口在控制器层复用同一进行中标记，避免按钮、键盘和旧监听器并发发起重复导入、保存、预览、导出或回退。

## 已完成步骤的回看与修改

已完成阶段默认显示只读事实，不渲染可编辑输入框或保存按钮。页面明确说明回看不会改变当前进度，并提供“返回当前任务”。

用户点击“修改此步骤”后，页面根据修改目标展示保守的影响清单。例如修改部署流程可能要求重新确认地图阶段，并使标记、定位路线和导出状态重新接受权威校验。

确认层遵循以下规则：

- 明确显示将回到的阶段。
- 分别标示“需重新确认”“将失效”或“保持锁定”的后续阶段。
- 说明不会因为进入编辑模式就删除地图文件、现场数据或项目快照。
- 提供“取消，继续回看”和“确认回退并修改”。

确认只进入本地编辑模式，不直接篡改服务端阶段。用户保存修改后，页面使用现有 API 获取新的项目事实，再由 `deriveDeploymentWorkflow` 计算实际完成、当前和锁定状态。若保存失败，保持原权威状态与只读回看，不产生半回退状态。

不同修改的实际影响由服务端已有校验决定；前端影响清单是操作前的保守说明，不能替代 Backend 校验。

## 组件边界

为避免继续扩大 `deployment.js` 的渲染职责，新增能力按以下边界组织：

- `deployment/workflow.js`：全局阶段和阶段内任务的纯推导、解锁和影响范围计算；不操作 DOM、不发请求。
- `deployment.js`：协调现有请求、刷新权威事实、切换回看/编辑状态和焦点管理。
- `deployment.html`：保留现有 DOM id 和 API 事件入口，重排为项目栏、阶段轨、任务区、工作区和只读进度栏。
- `deployment.css`：实现单一任务布局、只读回看、确认层、响应式与明暗主题。
- `deployment/session-state.js`：只保存视图偏好和未提交草稿；不得保存阶段完成状态。
- `frontend/test/deployment-workflow.test.mjs`：验证纯推导与页面结构约束。

现有地图画布、组件编辑器、定位路线编辑器和流程编辑器继续复用。它们只在相应任务成为当前任务时挂入工作区，不复制第二份实现。

## 可访问性与主题

- 阶段轨使用真实按钮；当前阶段使用 `aria-current="step"`，锁定阶段使用 `disabled`。
- 当前任务变化后把焦点移动到任务标题或首个必要输入，并通过礼貌级 live region 宣布成功或错误。
- 确认层用于保护会影响后续成果的操作，打开时管理焦点，`Escape` 等价于取消，关闭后焦点回到“修改此步骤”。
- 所有主操作支持键盘；焦点环在浅色和深色主题中均清晰可见。
- 输入正文在移动 Safari 等环境下不低于 16px，避免聚焦时页面自动缩放。
- 明暗主题保持相同信息层级和状态语义；不能出现浅色页面中的深色孤岛、低对比提示或不可读表单。
- 长项目名、地图名和服务端错误允许换行或截断后查看完整内容，不能撑破网格。

## 错误与边界状态

- 无项目：只显示创建项目任务。
- 项目存在但无部署流程：只显示配置部署流程任务。
- 导入文件不完整：在文件清单附近指出缺少或冲突项，保留可继续使用的选择。
- 车端建图运行时不可用：停留在来源/准备任务，说明运行时边界，不展示无效“开始建图”入口。
- 拓扑未通过：定位或导出阶段停留在可恢复任务，并显示服务端首个有效错误。
- 网络断开或超时：保留当前任务和输入，提供重试；不能把本地乐观状态当成已保存。
- 服务端事实被其他标签页更新：下次刷新后重新推导任务，并显示“项目状态已更新”，不覆盖新的服务端事实。
- 回退修改失败：退出进行中状态但保持原阶段和原项目快照，不自动重试。

## 测试与验收

### 纯逻辑测试

- 每个全局阶段的首个、进行中、完成和锁定状态。
- 地图五个子任务按单张地图闭环，完成一张后选择下一未绑定阶段。
- 每个状态恰好返回一个主操作。
- 成功响应后重新推导并自动进入下一任务。
- 错误或超时保持当前任务。
- 已完成阶段只读回看不改变 `current`。
- 编辑影响范围按修改目标保守计算，实际保存结果仍由服务端事实决定。

### 页面与交互测试

- 页面只有一个主操作区域；右栏没有第二个编辑入口。
- 请求进行中防止按钮、键盘或旧监听器重复提交。
- 成功回执、错误反馈、焦点移动和 live region 内容正确。
- 已完成步骤默认不出现输入框；“修改此步骤”打开影响确认层。
- 取消确认不改变任何状态；保存失败保持原流程事实。
- 既有地图画布、流程编辑、组件编辑、定位路线和实验下载 DOM id 与请求路径保持不变。

### 视觉与响应式检查

- 1366×768、1600×900、1920×1080。
- 200% 浏览器缩放。
- 浅色与深色主题。
- 长项目名、长地图名、长错误文本和空状态。
- 键盘顺序、焦点可见性、确认层焦点回收和 `prefers-reduced-motion`。

## 兼容与迁移

- 保持部署页面 URL、现有 DOM id、请求路径和响应解析不变。
- 保持 `deriveDeploymentWorkflow` 为五阶段事实入口，并为旧调用保留现有返回字段。
- 新的阶段内任务推导只消费已有事实；不要求旧项目迁移。
- 现有 `viewedDeploymentStage` 会话状态继续兼容；旧状态若指向锁定阶段则回到当前阶段。
- 不修改 `shared/contracts/deployment.md`，因为本设计不改变跨端数据、API 或运行时边界。

## 已确认的设计决策

- 采用“单一任务指挥台”，不使用并排可编辑栏或固定双轨工作台。
- 地图逐张完成完整闭环，不按操作类型批量处理全部地图。
- 普通安全保存成功后自动推进；高风险或交付相关操作要求确认。
- 已完成步骤默认只读；修改前展示后续影响并确认进入编辑模式。
- 右栏只承担进度与事实说明，不提供第二条操作路径。
- 预览稿确定的桌面比例为约 1480px 最大工作台宽度、约 292px 只读进度栏和正常正文尺度。

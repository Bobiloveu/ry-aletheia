# 车辆软件资产设计

## 目标

让现场人员在 Aletheia 中查看当前小车全部已安装的 `ry-*` Debian
软件包及其版本，并维护一份与车辆绑定的软件资产档案。出现运行问题时，
人员可以导出一张自包含的 PNG 版本矩阵，随故障单提供给研发进行版本比对。

## 范围与边界

- 新页面位于 Desktop 控制台的“系统 → 软件资产”；Mobile 不消费此能力。
- 后端仅读取本机 dpkg 数据库，固定查询已安装的 `ry-*` 包；不执行安装、卸载、
  更新、APT 操作或任意 Shell 命令。
- 本功能不订阅或发布 ROS Topic，不读取/修改 Supervisor、定位、导航、底盘和
  安全配置。
- 软件版本、架构和安装状态是只读事实；车辆档案、包维护人和说明是操作员可编辑
  的本地资料。
- 页面不展示绝对安装路径、环境变量、命令行、dpkg 数据库原文或其他系统包。

## 车辆档案

车辆档案存入现有 `config/console.json` 的受控 `software_inventory` 字段，字段为：

| 字段 | 键 | 规则 |
| --- | --- | --- |
| 车号 | `vehicle_number` | 必填；去除首尾空白；1–32 个可显示字符。 |
| 车架号 | `vin` | 必填；去除首尾空白；5–64 个字母、数字、连字符或下划线。 |
| 车型 | `model` | 必填；1–64 个可显示字符。 |
| 项目/客户 | `project` | 必填；1–96 个可显示字符。 |
| 部署地点 | `location` | 必填；1–96 个可显示字符。 |

所有字段都拒绝换行与控制字符。首次进入、资料不完整或历史配置缺失时，页面保留
可读取的软件清单，但在档案区域显示“请补全车辆档案”；导出按钮禁用。

## 软件包发现与本地说明目录

`SoftwareInventory` 是新的 Backend 模块。它以固定 argv 调用：

```text
/usr/bin/dpkg-query --show --showformat <固定字段格式> ry-*
```

调用必须 `shell=False`、5 秒超时、空标准输入，并只解析包名、版本、架构和安装状态。
只保留状态为已安装、包名满足 Debian 包名规则且以 `ry-` 开头的记录；按包名排序。
无 dpkg-query、查询超时、非零返回或输出畸形时，返回受控的“当前无法读取软件清单”
状态，不暴露原始命令、路径或 stderr。

每个记录由以下字段组成：

- `package_name`：dpkg 包名，只读。
- `version`、`architecture`、`installed`：dpkg 只读事实。
- `package_filename`：根据包名、版本、架构显示的标准安装包名
  `<package_name>_<version>_<architecture>.deb`。页面说明这是标准化名称；dpkg 不保存
  操作员当初下载文件的原始文件名。
- `maintainer`、`description`：本地说明目录中的可编辑文本；未登记包显示“未登记”。

说明目录以包名为键保存在 `software_inventory.package_notes`。页面保存时仅接受当前
已发现包的键，避免把浏览器输入变成任意配置命名空间。升级后新出现的 `ry-*` 包会
自动显示为“未登记”，不会被遗漏；暂时未安装的包不会显示在当前版本矩阵中。

首次使用不会预置或伪造现场事实。页面可由维护人员为 `ry-runtime`、`ry-shmsdk`、
`ry-master-interfaces`、`ry-nav2`、`ry-livox`、`ry-elevator` 等已装包填写负责人和说明。

## HTTP 契约

新增 Desktop Web 消费的专用接口，记录到 `shared/contracts/software_inventory.md`：

| 接口 | 行为 |
| --- | --- |
| `GET /api/software-inventory` | 返回车辆档案、当前发现时间、受控查询状态及只读包清单与已保存说明。 |
| `POST /api/software-inventory` | 原子保存完整必填车辆档案和当前可见包的维护人/说明；返回更新后的资产快照。 |

成功响应禁止缓存。格式错误返回 `400` 和用户可操作的中文错误；dpkg 查询失败的 GET
仍返回 `200` 和 `inventory_status: unavailable`，使已保存车辆档案仍可编辑；保存前若
无法确认当前包名集合，POST 返回 `503`，避免过时页面覆盖说明目录。接口不供 Mobile
消费，Mobile 保持无调用。

## Desktop 页面与导出

新增 `software-inventory.html/js/css`，复用 Desktop app shell、浅深色主题和现有系统
页的表单样式。页面按以下顺序呈现：

1. 标题“软件资产”和说明：版本清单是当前车的只读快照，车辆档案与说明由维护人员保存。
2. 车辆档案卡片：五个必填字段、保存按钮、最后保存状态。未填写时以字段级提示说明。
3. 软件快照卡片：发现时间、已安装 `ry-*` 包数量、查询状态与刷新按钮。
4. 版本矩阵：包名、标准安装包名、版本、架构、维护人、说明。维护人/说明可原位编辑；
   包名、版本、架构及安装状态不可编辑。
5. “导出版本图片”按钮：仅在档案完整且快照可用时启用。

导出由浏览器原生 Canvas 生成 PNG，不引入截图服务或第三方上传。图片包含：RY
Aletheia 标识、生成时间（北京时间）、五项车辆档案、包数量、表格全部当前行和
“版本来自本机已安装 `ry-*` Debian 包”的说明。长清单按连续纵向行绘制；超过单张
Canvas 安全高度时分割为按序编号的多张 PNG 下载。导出文件名为
`ry-software-inventory-<车号>-<北京时间>.png`，车号仅以安全文件名字符表示。

## 错误处理与数据完整性

- 后端使用 `SettingsStore.save()` 的原子写入路径；保存失败不更新内存快照或页面状态。
- 页面保存期间禁用重复提交，并以 aria-live 文本显示成功或失败。
- 刷新结果采用请求序号，慢响应不能覆盖更新后的页面或导出快照。
- 无包、未安装 `ry-*` 包、dpkg 不可用和本地说明缺失各自有明确空态；绝不显示误导性
  “全部正常”。
- 导出只能使用最后一次成功读取且已显示的页面快照，不重新查询、也不使用隐藏数据。

## 验证与验收

1. Backend 单元测试覆盖：固定无 shell 的 dpkg argv、已安装 `ry-*` 过滤、畸形行与
   超时失败、版本/架构原样保留、说明合并、五项车辆档案校验和保存时的当前包键校验。
2. HTTP 测试覆盖：GET 成功/不可用、POST 成功、缺少车辆字段、未知包键和查询不可用。
3. Web 静态/Node 测试覆盖：系统导航入口、完整表单、版本字段不可编辑、导出按钮状态、
   Canvas PNG 导出和请求竞态保护。
4. 更新 `shared/contracts/README.md` 和新契约，列出 Backend/PC Web 消费者与 Mobile
   非消费者。
5. 运行受影响 pytest、`scripts/test-backend.sh`、`scripts/test-web.sh`；现场验证仅执行
   只读 `dpkg-query`，不安装、卸载、升级或重启服务。

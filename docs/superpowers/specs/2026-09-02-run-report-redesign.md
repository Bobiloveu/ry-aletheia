# 运行报告重构设计

## 目标

将 Aletheia 自动化测试生成的单文件 HTML 运行报告重构为适合现场归档、离线打开和打印的证据文档，同时修复共享主题根节点造成的浅色模式底色泄漏与局部遗留配色。

## 范围

- 重构 `RunManager._write_html_report()` 生成的独立 HTML；报告中心列表不改动其 API 或业务行为。
- 保留 CSV 伴随文件、既有字段、人工干预记录、内嵌 SVG 轨迹、内嵌 PGM 底图及下载后的离线可用性。
- 统一 `html` 与 `body` 的主题状态，确保浅色页面内容不足一屏时不会露出深色背景。
- 将手动控制页的视觉表面改为共享语义颜色，保持车辆控制、键盘、watchdog 和 ROS 调用不变。

## 非目标

- 不修改 ROS2、任务执行、轨迹采集、CSV 写入、报告下载路由或报告索引逻辑。
- 不将报告变成依赖网络、外部字体或外部脚本的页面。
- 不在报告中加入筛选、编辑、删除等交互式业务功能。

## 信息架构

独立报告从上到下固定为：

1. 运行身份与最终状态：报告名称、运行 ID、任务用例、开始/结束时间、状态胶囊。
2. 核心结论：计划、已执行、通过、失败/取消、通过率；用可访问文本与细窄进度条呈现，避免只靠颜色识别。
3. 运行上下文：任务文件、场景、社区/楼栋/单元/楼层/门牌、CSV 文件名。
4. 轮次结果：带状态标签的表格，窄屏下允许横向阅读。
5. 人工干预与停滞处置：独立证据表格；无记录时清晰说明。
6. 地图运行轨迹证据：每轮一个证据段；轨迹地图以白色画布承载，完整保留内嵌 SVG。

## 视觉语言

这是安全关键的桌面运维/证据页面，采用 Apple 风格的克制中性色：

- 页面底色使用浅暖灰 `#f5f5f7`，内容表面为白色，分隔线为低对比灰。
- 系统蓝仅用于标题辅助信息、链接和进度；绿色、橙色、红色仅表达状态。
- 使用系统字体栈，圆角约 14–18px，弱阴影仅用于主信息表面。
- 不使用大面积渐变、玻璃拟态、装饰图形或自动播放动效。
- `@media print` 移除不必要背景和阴影，避免跨页拆分表格行、摘要和证据段。

## 技术设计

- 报告继续由 Python 在服务器端拼接成完整单文件 HTML；CSS 内嵌于报告，以保证下载后无需访问 Aletheia 静态资源。
- 只新增报告内的语义 CSS 类，例如 `report-shell`、`report-summary`、`status-badge`、`section-card` 与 `evidence-card`；不改变既有 SVG 内容。
- 通过 HTML 转义输出所有运行字段；嵌入轨迹前继续保持路径必须位于报告目录、扩展名必须为 `.svg` 的现有边界检查。
- 共享主题由 `html[data-theme]` 作为唯一颜色变量根节点，`body.theme-light` 继续保留为旧页面兼容标记。`body` 最小高度为 `100dvh`。

## 验收标准

- 生成报告仍包含内嵌 SVG 和 `data:image/png;base64`，不暴露 SVG 文件系统路径。
- 报告包含用例别名、可读本地时间、轮次、人工处置与轨迹证据等原有信息。
- 报告 HTML 不引用外部 CSS、字体、JS 或图片资源。
- 浅色主题下，手动控制页面与内容不足一屏的任意页面不会出现深色底部带。
- 深浅主题都使用同一套语义色，并通过静态测试和浏览器截图验证。

# Aletheia Flutter Design System

本文件是 Flutter 移动端的顶层视觉约束。实现级令牌与组件主题位于
`mobile/docs/DESIGN_SYSTEM.md` 与 `mobile/lib/app/theme/aletheia_theme.dart`；
两者必须保持一致。

## 设计方向

- Professional / Industrial / Precise / Restrained / Modern。
- 面向可信局域网内移动机器人的专业 HMI，服务机器人运行、测试与诊断人员；它不是营销页面、游戏 HUD 或普通 SaaS 仪表盘。
- 当前视觉表达状态监控、实时可视化、测试与诊断能力。未来操作能力必须在架构、权限和交互上与只读观测分离，不能以装饰性“控制台”视觉暗示尚未提供的物理控制。
- 深石墨单主题：`#101415` 画布，`#181E20` 主表面，`#0C1011` 下沉区域。
- 主信号色为克制的浅青绿 `#9BC7C0`。`#8CC49A`、`#E2B46E`、`#DD837B` 分别只表示成功、告警和错误。

## 组件与交互规则

- 页面标题左对齐，优先表达当前任务与真实状态；状态优先于装饰，信息优先于动画。
- 三个一级 HMI 工作区（首页、观测、工具）共用左上角 Logo 与产品名；工具二级任务页改以清楚的任务标题和返回层级定位，避免品牌与业务标题争夺注意力。
- 使用 4px 间距节奏；控件、分组状态表面和面板半径分别为 10、14、18px。
- 面板使用细边框，无装饰性阴影、渐变、玻璃拟态、霓虹、扫描线或无意义动画。
- 触控控件最小高度 46px。系统 Material 按压反馈保留；不要增加自动循环动效。
- 动效只用于解释一次明确的上下文或状态变化：一级 HMI 入口以 140ms 淡入切换，工具二级页以 180ms 淡入并保留极短的水平方向提示，地图/相机工作区、连接状态和测试状态以 180ms fade-through 替换。首帧必须完整显示，不能为了动画让 Loading、错误或地图证据以半透明状态停留。
- 实时地图拖拽、双指缩放、实时点云、Pose 和视频帧保持直接响应，不添加补间、惯性装饰或循环动画；开关、选中态和按钮只使用短促的系统触摸反馈。尊重系统“减少动态效果”设置：保留 100ms 不位移淡变，移除位置移动。
- 实时地图中的颜色必须有独立语义：点云使用高对比青蓝，虚拟墙使用受限红色，真实车体轮廓使用暖色并以深色描边，异常仍使用 warning/danger。它们不复用导航选中态，且不能只靠颜色表达状态。
- 相机画面是实车只读证据，不叠加装饰性 HUD；在等待、离线、后台暂停或 WHEP 重连时以简洁状态文字代替冻结画面。

## 实时观测的视觉边界

- 静态底图、虚拟墙、点云和真实车体轮廓采用同一地图坐标与 viewport，但保持相互独立的绘制层。层级固定为底图 → 虚拟墙 → 未来真实轨迹（有契约时）→ 点云 → 车体。
- 地图应叠加低对比、基于真实米制坐标的自适应格栅；格栅和所有地图图层共享同一变换。格栅是空间尺度参考，地图左下角使用不遮挡证据的紧凑“x m / 格”比例尺，而不是把格栅当装饰纹理。地图外是连续的低对比 Workspace Canvas，不使用纯黑留白，也不能允许无限平移。
- 新的高频 Overlay 必须是画布或 GPU 图层，禁止“一点一个 Widget”。
- 不用点云刷新地图图片，不以装饰性视觉效果掩盖数据过期、断线或地图外坐标。
- 地图与相机必须是明确可切换的工作区。宽横屏的相机工作区可呈现一条主画面和两条辅助真实画面，但不是无约束的视频卡片墙；竖屏仍优先一条完整主画面。
- 地图和主相机画面优先占用可用高度；地图内只保留标题、全屏和刷新等轻量控件。连接状态、位姿、点云等持续读数应紧凑地贴近地图边缘（地图连接状态与位姿优先置于右下角），不得以不透明卡片遮挡地图证据。

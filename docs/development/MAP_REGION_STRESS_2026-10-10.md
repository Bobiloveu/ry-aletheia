# 部署地图通行区域识别压力测试 · 2026-10-10

结论：计算稳定性检查通过，但自动主区选择未达标。gk1/P1、P2 无起点时误选外部白底并将内部大厅/走廊归灰；指定诊断起点后可保留相应内部连通区。两张室外长图仍保留大片连接外部的白底。大图能完成处理，但存在约一秒主线程停顿。

范围仅为 Web 显示推断。没有修改算法、原始 PGM/YAML、项目标记或机器人配置，没有编译、打包、部署、重启用户服务。

## 输入与方法

四张输入均来自用户提供的 /opt/ry/data/maps 路径，并读取各自 map.yaml 与 map_walls.yaml。全部分辨率为 0.05 m/格、origin yaw=0；虚拟墙沿用 Backend parse_virtual_wall_segments 的解释，再按 Web 相同方式转为图像坐标。没有混用之前的 PCD 重新投影结果。

每图四种场景各运行三次，共 48 次：无虚拟墙基线；已有虚拟墙自动选区；已有虚拟墙加世界坐标 (0,0) 的诊断起点；在原始空白块构造一个 2×2 m 完整虚拟墙框并指定框内起点。最后一个场景是独立闭合断言样例，不能代表现场房间精度。世界 (0,0) 只是对照探针，并非用户实际部署起点。

所有轮次检查原始障碍保留、floor 不覆盖障碍、输入 RGBA 未变和重复结果 SHA-256 一致；闭合样例额外要求 1,521 个内部格全白、框外非障碍格全灰。真实墙场景没有人工标注真值，机械断言不代表主区选对。

## 识别结果与限制

四图标准未知值 205 的格数均为零，背景主要是 254。故“原始未知占比≥50%”规则在这些输入上没有足够信息区分房间和走廊；少量抗锯齿中间灰度也不能还原已丢失的未知语义。

gk1/P1 自动选区保留 78.39% 白格、诊断起点变灰；加起点后白格为 10.95%、图幅边缘白格为零，图中大厅保留。gk1/P2 自动选区保留 72.40% 白格、诊断起点变灰；加起点后白格为 9.67%、图幅边缘白格为零，图中环形走廊保留。P2 探针落在电梯小腔附近，图中走廊与该腔仍有栅格开口，不能把此探针当作已确认的真实走廊起点。

自动评分主要按观测面积乘以墙边界支持权重，权重最多两倍；这两张黑白图的外部白底远大于内部通道，因此仍压过主区。需要进一步改进无起点时的候选区域判断；不能报告自动识别已通过验收。

gk1_outdoors/P1 自动和指定诊断起点结果相同，仍有 97.17% 白格；D_zone/lx3-nortk 两种结果也相同，仍有 88.04% 白格。二者图幅边缘仍有白格，已有墙线尚未让保留空间与外部完全隔离。这里只证明渲染仍连接外部，无法仅凭黑白底图区分真实开放路面与应灰化的外部空白；不能笼统地把所有室外边缘白格当作误识别。

四图分别完整保留 25,322 / 325,856 / 7,557 / 14,874 个源障碍格（含按现有显示阈值判定的抗锯齿格）；合计 373,609。新增显示补墙分别为 4,105 / 99,509 / 715 / 1,274 格。保留全部源障碍不等于新增补墙全部合理：没有门洞/墙缝标注，不能报告误封门洞率或规划正确率。

# 部署阶段目录与返程起点朝向

固定线路原先把最终起点朝向加了 180°，导致地图显示保存的起点方向，但导出 JSON 指向相反方向。
最终返抵起点现在直接采用起点保存的 x/y/yaw；预览、single 任务 JSON 与 multi 返程分段保持一致。
9 个回归场景覆盖 0、正、负朝向以及同图 single、跨图 single 和跨图 multi，逐个读取真实导出 JSON。

固定多任务导出原先把公共源图统一写到 `indoor/`。文件归属现在从保存的阶段分配解析，核对
部署流程、定位绑定及地图实例角色；不依赖地图显示名称，也不因地图里有电梯组件而改变阶段。

| 保存的阶段 | 既有多任务文件 |
| --- | --- |
| 摆渡层 | `sub_outdoor_eguard.json`、`sub_outdoor_eguard_r.json` |
| 电梯大厅 | `indoor/<楼栋>_<单元>.json`、对应 `_r.json` |
| 用户楼层 | `floor/<目标文件名>.json`、对应 `_r.json` |

当前固定多任务仍支持一个公共源图和一个连续用户楼层段。已有阶段顺序被反转、遗漏，或阶段与
实例、绑定角色冲突时明确拒绝编译，不把不支持的连接改名为其他阶段。旧无显式流程的项目
兼容以阶段类型为分配 ID 的规则。历史非固定任务编译行为不变。

目录映射复用已有契约和目录发现能力；每个分段仍为五字段直接任务 JSON，全部节点及动作引用
保持实际执行顺序。来源地图、项目保存的起点和全局摆渡归属不改写。

最终相关 Backend 检查 301 项通过、离线检查 109 项通过。当前真实项目临时副本导出 18 个节点，
公共文件是摆渡层根文件对、楼层文件保持一对，未生成 indoor；起点与最终返抵位姿完全相同，
yaw 均为 0。来源项目在验证前后相同。独立审查未发现重要问题。

两项修正合并构建为 `2.8.2-shm` 的升级 ZIP 和首次安装 DEB，保留既有 2.8.1 产物。
交付前核对 SHA256SUMS、ZIP 签名、ZIP/DEB 程序一致性、包内代码与源码一致性、默认配置路径和
惰性启动自检。旧实验包需重新生成。未安装到机器人、重启既有服务或下发任务。

Existing 消费者为 Backend 编译与目录发现、PC Web 预览和机器人任务文件读取；Mobile 不消费
部署预览，无新增 Mobile 工具链需求。结果不代表实车执行验证。

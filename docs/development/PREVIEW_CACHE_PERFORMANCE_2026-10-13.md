# 实验预览全流程性能与缓存验证

日期：2026-10-13。范围：部署任务预览、下载、退出重开及大地图压力测试。
补充 [路线预览记录](ROUTE_PREVIEW_2026-10-12.md)；此前浏览器算法测试不涵盖服务端首次编译。

## 复现与瓶颈

实际项目的只读副本、不加性能采样器的首次固定线路编译耗时 **32.785 秒**，
进程峰值 RSS 为 **1,515,996 KiB**。cProfile 单独运行耗时 49.194 秒，不作为用户延迟基线。
其中 `_map_path` 累计 40.402 秒、A* 40.360 秒，虚拟墙相交检查调用 573 万次。
固定线路已经明确访问顺序，只需确认各段连通，搜索出的最短栅格路径随后被丢弃。
自由像素还被展开成数百万个 Python 坐标元组，占用大量内存。

GET 恢复、POST 生成和 ZIP 下载此前都会重新编译。已有内容寻址导出目录只在
编译完成后去重，没有避免上述计算。

## 实现

- `FreeCells` 以每像素一个字节保存自由空间，用原生 `bytes.translate` 执行阈值映射。
- 固定线路使用双向启发式连通性搜索；每格最多发现一次，不维护最短路代价和前驱字典。
  保留原校验器的八邻域、最近自由格回退、虚拟墙端点相交语义。
  虚拟墙按空间桶筛选，精确相交仍使用原函数及原单元中心计算。
- 只改变编译时的连通性校验；实际小车路径、任务顺序、速度和导航安全配置不变。
- 项目自己的 `exports/preview-cache.json` 保存预览缓存索引，发布产物仍在
  `exports/<input_sha256>/`。GET、POST、下载共享同一缓存，并合并并发预览请求。
- 输入签名覆盖项目事实、地图/YAML/点云/虚拟墙文件实际内容、擦除/补墙、模板、状态码、
  组件默认值及编译相关代码。读取缓存前核验发布清单及每个产物的大小和 SHA-256。
  文件损坏、缺失或输入变化时重新编译；缓存写入失败不丢弃已成功发布的实验包。
- 代码签名规范化提取目录、字节码常量中的元组和无序集合，避免安装包提取路径及
  Python 哈希随机种子使重启后的缓存失效。已用不同种子的独立进程验证。
- 浏览器重开仍向 Backend 核对缓存，覆盖另一浏览器保存及外部源文件变化；
  后端命中时不重编译，已有美化与路线 Worker 结果继续复用。

## 本机测量

以下使用 Pixi 锁定运行时、独立端口的 QA 页面及 `/tmp` 中项目副本。
原项目 JSON 和 `/opt/ry/data` 文件保持不变；无打包、构建、安装或现有服务重启。

| 测量项 | 结果 |
| --- | --- |
| 原项目首次纯编译，优化前 | 32.785 秒，峰值 RSS 约 1.45 GiB |
| 同项目首次纯编译，第一轮优化后 | 2.221 秒，峰值 RSS 76.5 MiB |
| 导出一致性 | 22 个产物的路径、SHA-256 与总输入指纹全部一致 |
| 实际页面首次点击到路线显示 | 2.920 秒；其中服务端约 2.544 秒 |
| 原地图首次美化 | 1.941 秒，单独点击测量 |
| 已美化预览连续退出重开 5 次 | 94.3–112.7 毫秒 |
| 重开期间计算任务 | 后端仍只编译 1 次；美化和路线 Worker 消息数不增加 |
| 独立进程读取原项目持久预览 | 77.5 毫秒，编译次数 0 |
| 修改起点朝向后重新打开 | 约 2.608 秒，编译次数由 1 增至 2 |

可重复的服务端基准：

```bash
pixi run --frozen --no-install python scripts/benchmark-task-preview.py deployments/1
```

该脚本先复制项目到临时目录，测首次、5 次重开、下载和重新创建 Store，
断言只编译一次、重复预览完全相同且源项目 JSON 未变。一次复测首次 2.900 秒、
缓存 50–69 毫秒；ZIP 压缩约 986 毫秒，单独计时。

## lx3-nortk 大地图压力测试

只读输入：`/opt/ry/data/maps/D_zone/lx3-nortk/{map.pgm,map.yaml,map_walls.yaml}`。
原图 **3480 × 10017 = 34,859,160 像素**，分辨率 0.05 米，**450 段虚拟墙**。

算法测试在最大封闭可通行连通域内选取有效访问点，保留虚拟墙及原始障碍。
最初人工试选的部分坐标位于障碍或不同连通域，被正确拒绝，未作为成功路线测速。

| 大图测量项 | 结果 |
| --- | --- |
| 浏览器规划网格 | 712,638 格，未超过 900,000 格预算 |
| 网格构建 | 152 毫秒 |
| 长距离单段规划 | 37.9 毫秒 |
| 32 个访问点及反向返程 | 63.6 毫秒，失败段 0 |
| 20 次重复路线请求均值 | 0.111 毫秒 |
| 沿输出路线碰撞抽样 | 10,472 点，均处于允许通行网格 |
| 完整 QA 页面首次编译到路线显示 | 2.342 秒；服务端 1.705 秒 |
| 页面 CPU 降速 6 倍后，5 次缓存重开 | 0.779–0.844 秒，后端仍只编译 1 次 |
| 同条件首次美化，单独点击 | 9.880 秒 |
| 美化完成后同条件连续重开 | 0.762–0.829 秒，保持美化视图，无 Worker 重算 |
| 独立进程读取大图持久预览 | 130 毫秒，编译次数 0 |

完整页面夹具把这张图作为来源图，添加 30 个仅访问目标及跨图返程，使用现有项目的
用户楼层、物理电梯配置和受控点云作为编译夹具。它用于压力测试，未将这些夹具写入
机器人运行目录，也不代表该地图的真实部署模型。

CPU 降速仅设置于浏览器页面，不能据此断言 Worker 和 Backend 都被同倍数降速。
首次美化、首次任务编译、首次路线规划分别计时，不能把算法时间当作整个页面延迟。
缓存重开仍需源文件与产物审计，现场磁盘和网络速度会影响这些数值。

## 回归与边界

覆盖 ROS 占据阈值/反相、随机地图与原校验器等价、斜向连通、虚拟墙端点、
非整数分辨率浮点边界、空间桶交界、损坏缓存、地图/标记/线路/模板变更、
多请求合并、Store 重建、模板提取目录变化及不同 Python 哈希种子的独立进程。

Backend 定向检查 159 项通过，Web 单元 558 项通过，离线检查 109 项通过；
Web parity、Backend/Web Doctor 通过。未运行构建及安装包测试。

完整 Backend 回归耗时 1080.69 秒：1192 项通过，1 项失败。失败项为页面图片
错误处理变量改名后仍查找旧变量的静态断言；已同步为当前实现，并单独复验该项及
缓存、连通性检查，共 20 项通过。该完整回归启动早于最终修正与新增测试，
未将其记录为最终源码的全量通过。

没有变更 HTTP/ROS/WebSocket 或共享数据模型，Mobile 不受影响。
缓存范围仍限实验产物，不安装任务、不调用 ROS 或 Supervisor。
并发编辑与发布之间的旧事务边界未在本次改造为跨请求事务锁。

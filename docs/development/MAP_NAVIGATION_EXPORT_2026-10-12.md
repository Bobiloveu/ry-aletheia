# 部署包导航 PGM 导出修正

用户要求部署包中的小车地图与标记地图步骤的原始黑白底图一致，并明确确认未知格也导出为白色自由空间。美化图只用于显示。

## 定位与实现

既有导出未混入美化 PNG：`location_manifest._map_members` 从项目地图快照读取原始 PGM/YAML，叠加保存的擦除记录。实际差异来自点云投影地图中大量未知格 205。参考 `/opt/ry/data/maps/gk1/P2/map.pgm` 基本为 0/254，原文件不变。

导出复制时，对 `negate: 0` 或缺省的地图只将 205 转为 254；其余像素保持原值。`negate: 1` 的外部地图不套用此规则。YAML、分辨率、尺寸、原点和配套 `map_walls.yaml` 不变；不将美化轮廓或组件图标写入栅格。未含 205 的文件保持原字节。所有转换仅发生在返回的导出副本中，项目底图和点云投影结果继续保留未知语义。

新增读取路径同时暴露既有 P5 CRLF 头解析偏移：原实现只跳过 CR，导致 LF 被误当首像素。已用失败回归验证，再修正为跳过 CRLF 分隔，不吞掉二进制像素本身的空白或 `#`。

## 第二轮：原始画布与导出墙体缺口对照

第一轮只核对黑白/未知值，遗漏了导出擦除几何与实际 Canvas 的差异。用户圈出的电梯入口和左侧墙体缺口，来自 `_rasterize_map_edits` 多擦了地图：方形笔刷直接擦除扩大的候选包围盒，并在采样点之间额外插值；世界坐标到像素中心存在半格偏移；多边形原先使用偶奇填充，且未区分边缘的部分覆盖。

本轮按 `erase-preview.js::paintEraseOperation` 的原生图像坐标修正：

- 方形笔刷仅绘制保存的每个采样点，按矩形与像素的交集面积累积覆盖率；不擅自连接离散采样点。
- 圆形笔刷使用圆头线段的并集，边界带 8×8 覆盖率采样，并保留 Canvas 额外绘制首点圆盘的行为；扫描范围限制在线段附近，避免长斜笔画遍历整个包围盒。
- 多边形采用非零绕数，按顶点及边交点拆分扫描线区间并精确积分像素覆盖面积；覆盖整个像素行的内部区间通过切片写入，仅边缘计算裁剪面积。
- 覆盖率按 source-over 累积，达到半格时输出白色 254，其余保留原障碍值；不会把不到半格的边角擦成完整缺口。

使用真实 gk1 项目的两张底图及共 20 条已保存擦除记录，在浏览器直接导入实际 `paintEraseOperation`，原生分辨率渲染后与导出对照。按原始黑色障碍的擦除结果统计：电梯大厅此前额外擦除 27 格、用户楼层额外擦除 56 格；修正后均为 0。用户楼层（本次截图所示）的黑白墙体结果完全一致；大厅仍有一个边缘像素差异：Canvas 抗锯齿灰度 128，导出保留黑色，没有形成额外缺口。Canvas 的 Skia 抗锯齿与独立栅格化边界覆盖并不保证任意曲线的逐字节一致，不把这次结果扩展为所有图形的完全像素等同。

新增 12 组回归覆盖采样点间隔、半像素边角、圆头线段、退化/反向线段、多边形重复绕行与低于/高于半格的细长多边形；全部同时与真实浏览器 Canvas 核对通过。相关 Backend 测试最终为 303 passed、1 deselected（同上既有 Web 静态断言）；`scripts/test-backend.sh` 加 `PYTEST_ADDOPTS=-x` 复现该断言，221 passed 后停止，未宣称全量通过。

最后一次只读项目编译约 0.117 秒。1000²完整框选测试约 0.010 秒、5000²约 0.074 秒，用于验证内部快速路径；不代表任意复杂多边形或整包压缩的耗时。项目 JSON、两张源 PGM/YAML/虚拟墙文件编译前后 SHA-256 一致。

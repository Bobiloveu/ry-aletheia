# 地图建筑平面美化层 · 2026-10-12

按用户最终要求，部署地图只呈现两类空间：已有通行区纯白，未知及不可通行区为完整灰色块面。灰区内的原始扫描碎点、家具轮廓和扫描纹理全部隐藏。沿白色区域生成统一灰蓝色轮廓，保留通行区的孔洞、拐角和入口几何，不凭空识别房间或设备。

这是 Web 显示与 PNG 图片层改动。原始 PGM/YAML、虚拟墙文件、Backend API、导航规划及已识别通行区均不变；“原始”视图继续提供全部原始黑白点。没有构建、编译、打包或部署。

## 实现

- `map-cleanup.js` 保留现有识别、补缝、虚拟墙闭合和障碍证据，仅将最终显示改成白色 `#ffffff` / 灰色 `#e7ecf2`。美化视图的扫描点池为空，避免缩小显示时把隐藏点再次覆盖到灰区。
- 新增 `map-architecture.js`，从既有 floor mask 精确追踪有向边界，合并共线边为轮廓顶点。孔洞及对角接触分别闭合，描边使用 `#8b99a7`，不做改变空间分类的几何平滑。
- 轮廓工作在 Worker 中完成，并烘焙到原生尺寸美化图层；图片导出共用该图层。灰区不添加装饰纹理或虚构的设施。
- 缩小视图直接复用原生美化 bitmap；放大时只提交与视口相交的边。部分裁剪轮廓不闭合子路径，避免跨视口生成错误连线。
- 轮廓最多 25 万顶点，超限完整退回双色栅格。临时边标记数组为每格一字节，轮廓坐标使用 uint32；不随缩放累计缓存。
- 橡皮擦和框选擦除仍叠加在美化层之后，显示及 PNG 导出均擦成纯白。

## 后续修正：人工擦除入口的墙体描边

根因是保存的擦除在建筑描边之后直接覆盖白色，新开出的入口没有参与轮廓生成。新增 `map-edit-outline.js`：将保存的笔刷/多边形擦除与原通行区合并，重新生成局部双色图层和完整边界；入口口部和重叠擦除内部不生成封口线。实时未保存笔画继续提供原有白色预览，保存后完成描边。原始视图行为保持不变，导出 PNG 注入与美化视图相同的描边器，不再用白色覆盖生成后的边界。

## 先修正原图，再显式生成美化

地图现在默认打开黑白原始图。使用人员先擦除、补齐虚拟墙缺口，完成后点击右上角“生成美化”。准备原始图只做黑白显示和薄墙特征保留，不运行区域拓扑、美化或自动补墙。美化在 Worker 中显式生成，完成后切到美化视图并退出墙/擦除工具；切换原始/美化复用当前结果。生成时仍显示原图，可点击“取消生成”终止任务。

保存墙、起点、擦除或保护锚点变化后取消旧计算、清除旧导出结果、回到原始视图，并提示重新生成；编辑期间不连续重算。草稿、拖动和保存中禁止生成/导出。保护锚点使用服务端确认项目的独立坐标快照，组件保存失败、切图及返回不会把本地临时位置提升为确认依据。

生产图片通过 Worker 读取同源预览 URL 并解码，避免 UI 线程复制整张 HTMLImageElement；原始图准备期间不向 Canvas 临时上传整张源图。美化不再重复生成原始预览缓存。缩放、平移只绘制缓存，绘制函数不触发准备计算。接口、源 PGM、导航语义及通行识别算法均未更改。

## 多地图美化缓存与组件叠加层隔离

修正上一版失效范围过宽的问题：组件的坐标保护范围在默认 `removeIsolated=false` 下不参与美化算法，现在也不参与缓存失效校验。添加、移动、缩放、旋转普通组件及编辑普通标记仅重绘叠加层，既不清除已完成美化，也不取消进行中的美化。影响通行识别的虚拟墙、擦除及底图内容/标定变化仍会使对应地图结果失效，由使用人员手动重新生成；可选孤点过滤启用时保护范围继续参与校验。

缓存以项目 ID、地图 ID 定位，源校验包含 PGM 摘要、尺寸、分辨率、原点与文件路径，不使用每次切图创建的新 Image 对象或整个项目更新时间。每张地图保留独立的已完成显示引擎及解码图像；返回未修改地图立即恢复美化/导出，使用缓存原图引用绘制。其他地图的变更不影响本图。离开未完成计算时取消 Worker，迟到消息不能覆盖当前地图。

缓存属于当前页面会话，刷新网页会释放；默认最多保留 8 个地图记录和约 384 MiB 的估算缓存，按最近使用顺序释放非当前地图的位图。估算按每格 9 字节包含源图、结果和语义/轮廓余量，不等同于浏览器总内存；当前活动大图不会被自身限额驱逐。缓存淘汰后再次进入该地图才需手动生成。切回已缓存美化时不准备原始图，点击“原始”后才按需启动轻量原图 Worker；原始图准备期间可以立即切回美化缓存。

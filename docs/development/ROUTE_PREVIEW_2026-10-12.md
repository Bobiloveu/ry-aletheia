# 地图任务路线预览

## 问题与行为

原路线将任务位置直接连成折线，导致显示的路线斜穿墙体，无法表达经过门口和绕开障碍的过程。现在标记画布、任务线路配置和实验预览共用静态栅格路径规划，保持原有访问顺序和必经过渡点坐标。

这项变更只影响 Web 的路线显示，不修改任务位置、编译结果、地图导出或小车导航。预览不代表实车轨迹；实时障碍、完整车体形状和运动学约束仍由小车导航处理。

## 规划方式

1. Worker 读取当前地图原始 PNG，应用已保存的擦白、补黑编辑和虚拟墙。黑色障碍阈值与原始地图显示一致，透明区域视为障碍。
2. 保守聚合栅格，上限 90 万格，避免缩小地图时丢掉单像素墙。使用欧氏距离变换计算障碍距离，车型宽度的一半用于筛选可用栅格；车型来自现有只读设置接口，缺失时使用 0.68 m 默认宽度。
3. 使用带障碍距离代价的八邻域 A*，禁止对角穿过墙角。离障碍越近，代价越高，使走廊路线倾向于中间区域。
4. 对路径做视线简化，限制简化后的积分代价；使用二次曲线平滑转角，并对连接段重新检查可用栅格。按曲率自适应采样，误差阈值不超过 1.5 cm；压缩直线上的冗余点。每段保留准确的起终点，必经过渡点不会被平滑掉。
5. 位置不可用、路线不连通或达到计算上限时，显示原因并断开对应路段，不回退到直线连接。后续可独立规划的路段仍可显示。

原地图中值为 205 的未知区域沿用当前黑白显示的近似语义，增加规划代价而非全部阻断。这是显示层近似，不表示未知区域已被验证可以实际通行。车体宽度圆形近似、聚合栅格和离散采样也不构成实车碰撞保证。

规划思路可参照 [Nav2 Smac Planner 文档](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/planners_plugins/smac/)。当前实现是独立的浏览器预览模块，没有调用或替换小车 Nav2。

## 绘制与缓存

去程用蓝色实线和稀疏方向箭头，返程用橙色虚线。重合的去返程沿同一条规划中心线绘制，不为视觉分离而把路线偏移到墙体内。原始／美化视图共享规划输入。

主线程缓存最近 16 组结果，Worker 缓存最近 3 组地图栅格，每组最多保留 512 对位置的路径，反向路径可复用。地图、保存的修正、虚拟墙、车型宽度或访问坐标变化才使对应输入失效。平移、缩放和底图显示模式切换不会触发重新规划。

计算使用单个 Worker，最多一个正在执行的请求和一个可替换的最新待执行请求。旧地图返回的结果可进入缓存，但不能覆盖当前地图。

## 验证与影响

- 新增 16 项定向测试：墙体绕行、封闭障碍、窄门、虚拟墙、走廊平滑、必经位置、返程、旋转原点、地图边界、单像素障碍、对角穿墙、部分路段失败、计算队列与缓存恢复，以及长直线压缩、不整除／细长地图的保守聚合等价性、极长走廊压缩的工作量上限。
- Web 单元测试共 557 项通过；执行语法检查和前后端静态资源一致性检查。不运行构建或打包。
- 在只读本地 QA 服务中检查当前项目的摆渡大厅与楼层地图，实验预览两张地图均无规划失败；原始／美化切换、缩放、切图后返回复用结果。QA 服务拒绝写请求。
- 仅涉及 Web 展示和相应测试／文档。使用已有 GET 设置与地图接口，没有变更 Backend、Mobile、共享线协议或机器人控制边界。

## 性能复审

在同一个 Chrome 会话中开启 6 倍 CPU 限速，以同样的当前地图、保存的修正和虚拟墙交替运行优化前后算法，各测量 4 次。对照计算明确放在页面主线程执行，确保 CPU 限速作用于算法；实际应用继续在 Worker 内计算。以下为中位数，不代表所有低配置电脑的固定耗时。

| 地图与指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 大厅：栅格构建 | 672.5 ms | 526 ms |
| 大厅：路径搜索与整理 | 146.5 ms | 137.5 ms |
| 大厅：路线绘制 | 0.825 ms／次 | 0.249 ms／次 |
| 大厅：去返程顶点总数 | 1292 | 244 |
| 楼层：栅格构建 | 273.5 ms | 215.5 ms |
| 楼层：路径搜索与整理 | 43 ms | 42 ms |
| 楼层：路线绘制 | 0.273 ms／次 | 0.081 ms／次 |
| 楼层：去返程顶点总数 | 401 | 54 |

两张地图在全部对照中规划失败数均为零。优化前路线到新路线的最大几何偏差分别为 1.473 cm、1.420 cm；原始标记坐标不变。提速主要来自按行块聚合像素、跳过已确认阻塞的聚合格，以及减少直线和轻微弯曲的重复采样。

应用交互复测：连续切换地图 8 次，缓存命中没有新增规划请求，切图到恢复路线约 109–118 ms，首次缓存恢复为 311 ms。缩放没有新增规划请求。冷启动 Worker 请求在这次本机会话中为大厅 618.5 ms、楼层 217 ms，已有栅格时切换至编译路线为 25.8 ms；这些 Worker 耗时单独记录，不把页面 CPU 限速等同于对所有工作线程的硬件限速。

另外使用 704 万像素、32 个访问位置及反向返程的合成地图压力测试：本机 Node 栅格构建 91 ms，首次规划 257 ms，重复规划平均 0.072 ms，规划失败为零。合成数据不保存现场地图，不作为低性能真机测试的替代。

独立审查发现第一版直线压缩反复验证不断增长的线段，极长走廊上会出现平方级工作量。已将每次压缩的验证跨度限制在 10 m，继续保留障碍检查；用确定性的采样计数断言替代不稳定的耗时断言。1,000／3,000／10,000 格走廊的验证样本数为 31,398／95,598／320,298，随长度成比例增长。最大用例由第一版压缩的 40,081,652 次降至 320,298 次；独立复核后没有遗留阻断问题。

可复用的合成压力检查（同时断言必经位置顺序、可用栅格和计算规模）：

```bash
pixi run --frozen --no-install node scripts/benchmark-route-preview.mjs
```

耗时是观测值，不将某一台电脑上的绝对时间作为单元测试断言。

## 2026-10-13 窄通道首尾通行约束

任务线路编辑页此前把窄通道当作一个中心访问点，预览可能在组件中部转向。
现按 Backend 既有的旋转长轴规则展开入口、出口两端中心；轴线段独立检查障碍并保持直行。
实验预览保留服务端原始任务坐标，只给显示规划附加几何约束。途中经过但未加入线路的
窄通道，也在显示规划中使用两端中心，不从组件侧边抄近路。此类自动补充仅作用于显示，
不自动修改已保存线路、导出任务节点、速度或动作；要将组件通行语义导出，仍须将其加入任务线路。

外侧路段临时屏蔽通道内部，A* 边、路径压缩和曲线均执行精确矩形相交检查，避免旋转矩形
在栅格中心之间被切角。自动方向取自实际路径首次穿入位置，避免隔墙情况下按直线距离
选错入口。通行失败显示断段和原因；不将绕行伪装成穿过通道。路径对缓存键包含组件几何与
直行约束，组件移动、旋转或尺寸变化可失效，原始／美化切换及缩放仍复用规划结果。

新增 9 项回归覆盖两端、长轴旋转、重复经过、去返方向、阻断、途中组件、旋转侧边切角、
有隔墙的入口选择以及跨地图坐标隔离。Web 全部 567 项通过，语法与 parity 检查通过。
独立复查另扫 87 个旋转角度，未发现误阻断或外侧路段穿入组件。
当前项目只读副本的实际浏览器预览中，楼层去程及返程均准确通过
`(-3.4799721589, 3.7850640471)` 和 `(-3.4799721589, 5.8536680655)`，无规划失败；
原始／美化画面核对完成，切换美化未增加路线 Worker 请求。原项目及现场文件未修改，
未构建、打包或重启现有服务。本次仅修改 Web，不改变 API 或共享数据契约，Mobile 不受影响。

## 2026-10-13 起点附近降采样误阻断

当前 2320 × 3320 地图的第一段在 15 cm 预览栅格中被保守障碍合并阻断，但在原始
5 cm 栅格中可通行。不是起点漏选或连线漏画：原预览只能绘制后续成功路段。

Worker 现在只对失败路段尝试原始精度的局部规划，保留原始端点、已保存擦除／补墙、
虚拟墙、车体半宽及窄通道轴线约束。局部窗口包含端点外至少 2 m 的余量，最多
900,000 个栅格；超过预算、真实受阻或局部范围内找不到路径时，继续显示断段及原因，
不移动端点、不用直线兜底。成功路径和已尝试失败结果进入现有路径对缓存；缓存不持有
整幅原始 RGBA 图像。该修正只作用于 Web 预览，不改变机器人任务和共享契约。

验证：先复现回归测试失败，再修正；578 项 Web 测试、语法和 parity 检查通过。
当前项目只读复算用 50,838 个局部栅格恢复第一段，原起点坐标保持不变；浏览器实际
Canvas／Worker 的首段及再次请求的缓存结果一致，规划失败为零。未修改项目或现场地图，
未构建、打包、部署或重启现有服务。

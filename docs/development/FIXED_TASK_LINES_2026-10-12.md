# 固定任务线路与仓控核对（2026-10-12）

## 配置方式

地图准备 → 标记地图 → 配置任务线路 → 校验与导出。

1. 标记既有起点、目标点和过渡点。常开门使用过渡点，速度选 normal，无动作、无单点停靠。
2. 在任务线路中指定起点，按去程顺序添加门口过渡点、超市目标、返回经过的门口、电梯另一侧的送货目标。
3. 每次访问目标独立选择取货、送货或仅到达；取送货选择上仓 1 / 下仓 2，以及开仓、关仓或自动卸货。
4. 同一位置可以反复添加并指定不同动作。用上移/下移调整顺序，保存多条具名线路，选择本次实验使用的线路。
5. 系统根据现有电梯落点自动插入乘梯段，生成只读返程；返程不重复仓控。校验与实验预览通过后下载实验包。

定位用途、楼栋和单元自动取自地图实例，不再逐图确认。布局模板编号为稳定内部标识，实际按钮层仍来自物理电梯与落点配置。
未保存编辑、失效位置、不可达路段或不明确的跨图连接会阻止编译。设施不能作为末步，需添加出口过渡点或目标。

## auto_cargo.xml 的实际含义

核对来源：`/home/bob/Desktop/test/behavior_tree_template/waypoint_tasks/auto_cargo.xml`。

现有 Sequence 依次执行：

| 节点 | 含义 |
| --- | --- |
| GetTaskTargetInfo | 从当前任务获得 delivery_code 及 task_target_success 黑板值 |
| PublishTaskStatus 700 | 发布当前配送目标的开始状态，message 使用 delivery_code |
| CargoSingleCommand | 用 caogo_id 和 operation_code 执行仓控；端口 caogo_id 的拼写来自现有节点接口 |
| PublishTaskStatus 701 | 仓控成功后发布该配送目标的到达状态 |
| PublishTaskStatus 109 | 发布整单完成 |

Sequence 中前一个节点失败或仍在运行时，后续节点不会提前执行。XML 本身没有人工装货确认、等待关仓、超时重试或自动关闭步骤；开仓节点成功不能据此推断人员已装货完毕。

注释描述的是自动卸货模板，并非所有开关仓策略。当前实际单仓接口支持 1=上仓、2=下仓；操作码 0=开仓、1=关仓、2=自动卸货。XML 注释中的双仓 0 / 不卸货 -1 不直接作为新固定线路的单仓参数；新配置只接受已核对的单仓 1/2。

## 固定线路的编译处理

原模板不能直接在每个取货点执行：它包含配送状态和整单完成，还读取动态订单目标。因此每次固定目标访问生成独立 XML，使用本次访问的确定仓位/操作。取货只执行仓控；送货沿用 700 → 仓控 → 701。109 只在整条线路最终返抵起点时发布一次。仅到达目标不执行仓控。

电梯复用原有呼叫、门状态检查、地图切换和定位操作顺序，每趟写入固定楼栋、单元和实际目标层，避免被动态订单覆盖；不新增机器人节点类型。返程反转导航和设施通行动作，不复制目标仓控。

开仓方式沿用现有节点的成功条件，没有新增人工装货完成等待或自动关仓协议。此项保留为后续真实车辆流程对接点，不能用固定时长或假定成功代替。

当前跨图支持同楼栋单元内唯一共享物理电梯的地图连接。摆渡层已包含电梯大厅时，可省略独立大厅阶段，直接在摆渡图标记电梯并关联用户楼层的同一物理电梯；本次编译解析唯一楼栋单元，不改变项目的全局摆渡归属。其他未批准的户外/摆渡连接明确拒绝。没有 task_lines 字段的历史项目保留原 single/multi 编译器；新项目空列表或删除已选线路后阻止编译，不静默回退。

可达性使用 YAML 实际指定栅格，应用与导出一致的擦除和黑白规则并考虑虚拟墙。同次编译每图只解码一次。嵌套图像路径在导出 YAML 中同步改为包内位置，来源文件不变。

## 标记快捷编辑与朝向复测

目标快捷弹窗移除位置级“到达动作”（泄水/卸货），保留门牌号、尺寸与朝向，并提示在任务线路的每次访问设置取送货和仓控。同一位置可以复用；普通位置保存继续合并已有属性，历史 arrival_action 不被删除或改写，也不自动迁移历史项目的编译模式。固定线路执行仍只消费该次访问的 action。

## 固定线路导出名称（2026-10-13）

任务 JSON 使用“小区名_线路名.json”，ZIP 使用同一名称加 `_experimental.zip`，例如
`高科一号_超市取货.json` 与 `高科一号_超市取货_experimental.zip`。

行为树使用“动作执行序号_英文用途_线路名.xml”，例如 `01_start_task_超市取货.xml`、
`02_pickup_upper_open_超市取货.xml`。序号按 JSON 中实际首次执行顺序统一补零，包含系统插入的
设备与乘梯动作；不表示卡片序号或楼层。`pickup/delivery` 表示取送货，`upper/lower` 对应
上仓 1 / 下仓 2，`open/close/unload` 表示开仓、关仓、自动卸货。
`outbound_elevator_call/ride/close_door` 与 `return_elevator_call/ride/close_door` 区分去返程。
最后一个动作使用 `task_complete`。普通过渡点不生成行为树。

同项目同名、清理非法字符后同名、UTF-8 截断后同名的线路增加可读编号。内部点位 ID 仍稳定，
所有 `waypoint_task_id` 与 XML 文件名、清单哈希一起更新。不要单独改旧包中的文件名；重新生成
预览并下载即可得到新命名。既有历史 single/multi 模式不变。

的文件排序和下载文件名。源码只改 Backend 导出与必要的契约/验证文档，不写现场项目或运行目录，

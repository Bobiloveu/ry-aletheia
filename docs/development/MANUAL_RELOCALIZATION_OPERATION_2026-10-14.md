# 手动重定位操作检查（2026-10-14）

范围：Backend 与 PC Web；Mobile 不消费该功能，遥测线格式不变。工作树已有大量现场开发变更，本次仅修改手动重定位、受控停车回调及相应契约、文档和测试，不移动目录，不覆盖现场配置。

## 事实与修复

实车 2.8.9，Lightning 1.6.5+compatible.5。只读日志显示一次开始失败发生在 miniapp 已确认后，原因是当前地图无法确认。实车只读参数查询同一个客户端首个请求超时，第二个新请求立即返回当前地图。Backend 改为保留独立节点/client/executor；每次仍发新请求，仅首个响应超时允许一次重查，不使用缓存，不重试实际 Relocalize。关闭控制台时释放该查询资源。

另一个独立问题是切 miniapp 的过渡期间 navigation 心跳被立即判失败。现在保留切换等待且不延长 4 秒期限；超时后的 miniapp 反馈不能重新激活。对齐中失去停车控制权立即禁用编辑；两阶段实际发送前、等待确认中及恢复前重新核验停车占用。

用户明确要求手选配置支持定位地图恢复，故不再要求 YAML 的 system.map_path 等于当前二维地图目录。配置仍必须在受控目录内、可读、有界、无歧义且指向现有绝对地图目录。初始化发送前仍要求原二维地图不发生外部变化；发送后允许原地图或手选目标地图，其他地图变化拒绝。保留原文件身份/内容二次核验，不复制或修改 YAML，不主动调用 map_server 切图。所选配置加载的是定位地图，界面二维地图独立跟随 map_server。

PC 所有动作单次在途，旧 GET 不能覆盖新 POST；提交后停止拖拽且锁定配置。候选使用原始 map 位姿，点云与代价地图共用 T_target * inverse(T_live)；移位保留抓取偏移，旋转保留相对角度。初始化结果到达后清空旧动态层，等待新实时位姿再清除预览，重置速度估计和显示预测；等待期间拒绝动态层，接管时重新建立时间戳屏障。无新反馈超过既有 450ms 新鲜度窗口即结束预览并显示等待，不把目标当真实定位结果。

## 定位配置目录浏览性能

只读实车测量：定位目录一层扫描为 0.1–0.4ms，本机 HTTP 浏览约 1–3ms；同一浏览接口从开发电脑访问曾达约 2.16 秒。优化集中于 Web 避免重复往返：同路径在途请求合并、本次操作内 15 秒有效的最多 20 个目录列表缓存、每层最多 6 个直接子目录串行低优先级预读。关闭或导航离开时取消无用请求，单次读取 5 秒超时可重试，预读失败立即停止。缓存只含目录元数据，不读取 YAML 正文；自动模式和本次操作重置会清除缓存与选择。Backend 提交前的文件、地图与运行身份校验不变；接口与 Mobile 无变更。

每次请求固定延迟 600ms 的隔离浏览器对比：进入下一层/返回上级/重新展开分别从 615/615/607ms 降到 11/10/10ms，首次读取仍约 600ms；该流程请求从 4 次降为 2 次，包含预读。完整实时观测页的目录导航、文件选择、取消和按钮状态已用本地模拟服务验证，浏览器无错误；未向实车发送控制操作。13 项选择器测试、763 项 Web 全量测试、生产构建、Web doctor 与独立代码审查通过。本次未打包或部署。

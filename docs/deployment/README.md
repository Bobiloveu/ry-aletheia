# 部署文档

## 定位与边界

PC 部署工作台是一个**引导式、模型驱动的受控预览部署编译器**。它将容易出错的手工任务编辑转为地图标记、组件属性和可校验的项目模型：系统从地图阶段、标记、定位路线和受管行为树模板派生任务预览与 ZIP，并在生成前校验路径、拓扑、设备号、组件执行链和行为树引用。

当前输出始终是项目工作区内的实验预览和下载 ZIP；它不写入机器人任务、行为树、定位或运行目录，也不会启动 ROS、Supervisor 或下发任务。预览通过后，仍须由人工确认并按现场交付流程安装。这使其属于试运行部署流程，而不是无确认的一键上线。

## 日常操作

1. 创建项目时选择车辆任务模式，并配置户外图、摆渡层、室内大厅或用户楼层；四类均可独立使用。
2. 导入或车端建图后完成地图标记、组件属性、虚拟墙和任务线路。新项目的每次目标访问明确选择取货、送货或访问，并按需指定仓位和开关仓/卸货动作；泄水（`place_water.xml`）与卸货（`auto_cargo.xml`）的位置级选项仅供历史编译入口兼容。
3. 保存线路与小区名称后生成实验预览。新草稿可直接保存；已有流程点“新建线路”会保留配置并解除原线路 ID，保存时不覆盖原线路。通过校验后下载 ZIP，交由人工确认后的安装流程处理。
4. 在“校验并导出”完成态点击**新建其他项目**，即可立即填写新项目。原项目不会删除、覆盖或重新编译，并持续保留在项目列表中，可随时切回。

地图阶段采用可拖拽的 `deployment_flow`，至少一个阶段，用户楼层可选且如有则最后；户外图、大厅、用户楼层各最多一个，摆渡层可重复。单图固定线路的 single 输出完整往返任务，multi 仅输出该阶段的去返文件；独立用户楼层多条送货线路各自导出 floor 文件对。跨图仍以实际连接和当前模板范围为准，不支持任意转场。部署项目删除只清理项目工作区，不触碰机器人运行目录。

新固定线路导出的 XML 文件名、`waypoint_task_id` 与 `waypoint_id` 使用 ASCII，界面中文名称保留。速度模式不是单纯的速度数值；源码范围、用户指定参考树及缺口见 [速度模式模板基线](../development/SPEED_MODE_TEMPLATES.md)。

机器人发布、DEB、升级、配置和视频运行时说明保留在 [PROJECT_OVERVIEW](../../PROJECT_OVERVIEW.md) 与根目录构建脚本中。修改面向客户端的地图或部署行为前，阅读[部署契约](../../shared/contracts/deployment.md)。

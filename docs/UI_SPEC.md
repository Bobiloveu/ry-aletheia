# Aletheia Flutter UI Specification

## 产品定位

Aletheia Flutter 是面向移动机器人的专业 HMI（Mobile Robot HMI / Test & Diagnostic Console），将机器人状态监控、实时可视化、测试诊断和测试任务管理组织为统一移动端入口。一级信息架构按用户目标组织，不按 Pose、PointCloud、WebRTC、Test Case 等内部技术或业务对象命名。

## 当前范围

移动端当前提供四个一级入口：首页、观测、工具、设置。首页承载当前机器人的连接和健康概览；机器人相关数据来自现有
Aletheia HTTP 或只读实时遥测接口。当前版本提供监控、观测、测试与诊断能力，不暴露底盘、导航、ROS Topic 或相机硬件控制。

## 一级信息架构

- **首页**：未连接时输入或恢复机器人地址；连接后显示控制台、遥测、预处理和地图缓存等健康状态。连接是首页内的状态与操作，不再单独占据一级导航；“首页”描述操作者进入 HMI 后的起点，而非将机器人这个业务对象误作导航名称。
- **观测**：地图和相机两个按需切换的实时工作区。Pose、PointCloud 和视频都属于观测数据，不单独成为导航入口。
- **工具**：对当前机器人生效的低频能力。自动化测试位于“工具 > 自动化测试”，其下再进入用例库；“用例”和“运行”均不作为一级导航。用例库适配既有的 JSON / `.rycase.zip` 导入导出、别名、版本、生命周期、标签、说明与场景绑定。测试详情显示既有 Supervisor 预检、停滞处置、人工恢复、轮次结果和只读轨迹证据；停滞处置只记录到当前测试，不构成机器人操作。诊断日志提供既有日志包与诊断文件下载；测试报告提供浏览、下载与确认删除。运行配置、场景前置配置和控制台服务都位于工具二级页，并只能调用既有的受控 API。场景文件必须先在受控目录内预览内容、大小与 SHA-256 摘要再选择；移动端明确不提供离线升级 ZIP。
- **设置**：独立的应用级入口，不是机器人工具。它只管理本机语言、HMI 深色显示偏好、版本信息、App 更新检查和问题反馈；不要求连接机器人，且绝不写入机器人配置。App 更新与机器人离线升级目录完全隔离：当前开发构建只展示本地检查结果，未来必须接入经审核的应用发布渠道。问题反馈进入独立表单，可填写问题或建议、联系方式，选择最多三张截图，并选择是否附加仅含 App 版本、平台、语言、主题和本次 App 会话事件的诊断摘要。当前开发版本只完成本地校验，不上传、不保存表单内容；未来上传必须替换独立的提交接口，并在用户确认后只发送表单中可见且已选择的字段。
- 测试历史与更详细结果仅在对应只读车端接口接入移动端后加入工具页，不能用静态占位数据假装可用。
- 品牌 Logo 与产品名在“首页”“观测”和“工具”三个机器人 HMI 工作区保持一致，用来建立进入应用时的身份识别；观测顶栏是透出底图的低不透明度状态材料，而不是把地图切断的实心留白。设置是本机应用级页面，使用明确的“设置”页标题，不显示机器人连接状态或重复品牌条目。工具二级页面以本页任务标题、返回路径和真实状态完成定位。

## 未来操作能力边界

- 当前不增加“控制”一级入口、空白路由或占位功能。是否成为一级入口取决于真实机器人操作场景、权限模型和使用频率，而非视觉完整性。
- Observation / Monitoring 保持只读：地图、Pose、PointCloud、视频及其状态 Provider、Repository 和实时通道不得承载机器人命令。
- 未来的 Robot Operation / Command 必须拥有独立领域、路由、状态管理和后端命令契约，并在每次高风险动作前使用明确权限、目标确认与审计机制。
- 在上述契约真实存在前，产品文案只能说明“预留统一 HMI 入口”，不得暗示 App 已可直接操作机器人。

## 实时观测

- 先确认车端观测配置与遥测状态，再读取活动地图缓存。缺失地图、不可用遥测和网络错误必须显示明确状态与可恢复操作。
- 地图工作区按当前可用高度扩展，支持同一世界坐标下的平移与缩放。地图应作为有限 World Workspace Canvas 上的一层，单指平移的是整个工作画布而不是地图图片本身；画布格栅、地图、米制格栅和覆盖层必须随同移动。初始视图按 **cover** 保持原始长宽比并填满工作区短边，不能把纵向地图缩成横屏中的窄条或拉伸变形；地图四周必须留有可操作画布，使任意方向都可直接拖拽。双指缩放必须以两指中心为锚点，并把缩放与双指平移作为一个变换处理；旋转后保留当前中心世界坐标（包括地图外的画布位置），而不是复用旧屏幕像素偏移。地图切换时先等待新一帧 Pose/PointCloud，不能直接把旧图层留在新底图上。
- 图层从下至上固定为静态 PNG 地图、米制格栅、虚拟墙、未来真实轨迹（有实时契约时）、点云、车体轮廓。格栅、底图和所有实时覆盖层共用同一个 viewport/world transform；格距根据当前 pixels-per-metre 在 0.25/0.5/1/2/5/10/20m 间自适应。格栅是距离参照而非装饰：地图左下角以紧凑比例尺明确显示当前“x m / 格”，其横线长度等于一小格的当前屏幕投影。虚拟墙遵循车端 `world` / `image_relative` 坐标语义，并以稳定的细屏幕线宽呈现；车体由 active vehicle model 的真实长度、宽度、地图分辨率和当前缩放投影，不能使用固定像素图标。
- 地图外区域使用低对比、带弱格栅的 HMI Workspace Canvas，而非纯黑。画布为地图四周提供有限但可用的工作边距，既支持自由检查地图边界外区域，也不能无限拖离工作区。
- 点云使用高对比数据颜色，虚拟墙与车体轮廓使用互相可区分的语义色。地图工具栏提供全屏查看入口；横屏中工具改为左侧窄图标工具条，不在地图顶部铺设一整条标题栏。连接状态与实时位姿作为低对比的小读数置于地图右下角，不能遮挡地图、虚拟墙、点云或车体；断线或数据显著过期使用 warning，而不是伪造正常状态。
- 页面只保留实时观测所需信息。视频以独立相机工作区按需提供；实时轨迹和机器人操作不在当前 UI 范围内。未来操作能力必须遵循本规范的独立领域与权限边界。

## 相机工作区

- 竖屏通过明确的分段控件切换地图与相机；短横屏把切换动作合并到各自工作区工具栏，避免单独控件继续压缩主工作区。相机视图不构建地图/点云/Pose overlay；地图视图不创建 WebRTC 解码器。
- 相机读取车端状态中全部已配置流。操作者可独立启停每一路已配置流，并选择主画面；默认优先 `front_camera`，否则使用第一条配置流；启动/停止只提交已配置流的名称和布尔开关。
- 空间充足的横屏相机工作区最多同时建立三路真实 WHEP/WebRTC 解码器：中部只展示一条主画面，右侧原流选择区域用于两条可直接点击切换为主画面的辅助真实画面；各流开关与地图/刷新动作位于左侧控制栏，避免与顶部连接状态重叠而难以点击。竖屏与紧凑宽度只保留一个主画面，避免牺牲证据可读性。进程内全局解码上限固定为三路，第四路必须等待已有 renderer/PeerConnection 完整释放；不能为了缩略图或卡片预览无上限同时解码六路。每个 renderer/session 的建立与释放仍各自串行，旧 session 的异步回调不得写入已关闭 renderer。
- 只有车端状态为 gateway online 且对应流 online 时才建立 WHEP/WebRTC。等待相机、网关离线、WHEP 建连失败和应用后台必须停止/不创建解码器，并显示可诊断的状态。
- 视频以 4:3 原生渲染表面保持完整画面。不加入控制、分析或装饰性覆盖层。

## 响应式与可访问性

- 以手机竖屏单列和底部四项导航为默认入口；不锁定方向，也不假定使用者必须横屏。
- Flutter 的移动端设计变更必须同时审阅既有网页移动端实现：`frontend/src/liveObservation.css` 是观测工作区的移动优先参考，`autodrive_console/web/mobile_console.css` 是生产网页 `/m/` 页面的通用壳参考。应吸收其已验证的信息层级、竖横屏 Chrome 压缩、Safe Area 和地图/相机工作区取舍，但不可复制网页 CSS、过时调色或技术实现。网页的多格视频布局仅作为空间组织参考；Flutter 在宽横屏固定为最多三路真实 WHEP/WebRTC，绝不照搬六路无上限解码。
- 依据页面实际可用宽高而非设备名称适配：空间充足时可改用侧边导航与双栏相机工作区；短而宽的窗口压缩非关键说明和间距，让地图或 4:3 主相机画面优先获得可视高度。
- 短横屏的全局 Chrome 固定为 44pt 顶栏与 56pt 图标仪表导航条；导航条与 HMI 主画布共用背景，只用低对比分隔线表达结构，避免形成独立的深色槽。每个入口保持 44pt 触控目标，以中性抬升选中表面和信号色图标而不是文字标签表达当前一级模块。动态岛在尾侧时分隔线紧贴 56pt 导航条，最大化 HMI 工作区；仅在动态岛位于首侧时预留必要系统安全区。Tooltip 和语义标签保留“首页 / 观测 / 工具 / 设置”的可发现性。竖屏与较高的横屏仍保留当前完整导航表达。
- 自动化测试的运行详情要在进度附近呈现本次预检返回的 Supervisor 节点快照：名称、Supervisor 进程、必需/可选及真实状态。它是只读运行证据，不在移动端伪装为可直接启停机器人节点的控制台；无快照时明确说明等待预检，而不使用模拟节点填充。若既有轨迹监测返回停滞提醒，移动端显示“继续观察 / 已解除阻塞 / 判定本轮失败”三个确认操作；它们仅调用测试服务已有的 `stall-action` 记录契约，不能替代急停、导航或底盘命令。已完成轮次的 SVG 轨迹证据在系统内嵌浏览器打开，作为只读测试证据。
- 保留 Safe Area、最小 44pt 触控目标和受约束的最大内容宽度；竖屏、横屏、分屏与 iPad 都必须保持直接的返回和可滚动访问路径。
- Debug UI Gallery 在所有短边小于 600pt 的设备上直接渲染被选中的生产页面，并固定提供 48pt 的状态选择方格；方向切换、长边大于 900pt 的 Android 手机和布局约束先于 `MediaQuery` 更新的瞬间都不能令该入口消失。该入口仅存在于 Debug 构建。
- 不依赖色彩作为唯一状态表达；图标与文字必须同时表达通道状态。
- 保持系统字体和 Material 触摸反馈，避免妨碍直接地图操作的无意义动画。
- 动效是状态解释而不是装饰：一级入口使用 140ms 淡入，工具二级页使用 180ms 淡入与极短的进入方向提示；地图/相机、连接横幅和测试状态使用 180ms fade-through。首帧、地图与视频内容保持立即、完整可读；“减少动态效果”时退化为 100ms 无位移淡变。
- 应用设置使用系统熟悉的分组列表和可逆底部选择器。默认是 HMI 深色，并提供高对比深色与经过地图、相机、状态面板验收的“日间模式”。日间模式使用低反光冷白工作底和保留对比的语义色，绝不以纯白或简单反相损害地图、点云、虚拟墙、车体与告警的可读性。切换只改变本机配色，不改变机器人数据、运行配置或安全边界。语言偏好会立即切换设置页并写入 App Locale，其他页面按迁移完成度逐步本地化，不能将未翻译页面伪装为已支持语言。
- 问题反馈使用完整页面而不是外部浏览器或长 BottomSheet。标签位于输入框上方，提交前作内联校验。系统图片选择器只在用户点击“选择截图”时打开；选择的图片在开发阶段不读取、不上传、不保存。App 会话日志只保留内存中的有限 App 生命周期/反馈页面事件，进程退出即丢失。诊断摘要绝不能包含机器人地址、地图、视频、车端日志、ROS 数据或未在表单中明确展示的信息。
